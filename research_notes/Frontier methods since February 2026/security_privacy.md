Evidence labels used on every finding. Who measured: **vendor** = a lab reporting on its own model or product; **authors** = the paper's own measurement (arXiv preprint, not independently replicated unless stated); **independent** = measured by someone other than the vendor of the system under test. How I saw it: **opened** = page fetched and read; **full text** = arXiv HTML read; **abstract** = arXiv abstract only; **snippet** = seen only in a web-search snippet (host blocked or not fetched). ## 1. Prompt injection since February 2026: attacks, defences, lab-reported robustness, adaptive evaluations

### Takeaway
Frontier models became far harder to hijack in 2026 (vendor-reported single-attempt success well under 1%, a few percent after 15 to 100 adaptive attempts), but every lab and every adaptive-attack paper says model-level and classifier defences keep a non-zero miss rate, and the defences that held under adaptive attack are deterministic ones outside the model: capability or task-scoped authorisation, privilege separation, information-flow labels and removal of the exfiltration path. Detectors and "AI firewalls" look good on static benchmarks and degrade under adaptive attackers, low attack prevalence, other languages, other surface forms and non-instruction ("false fact", "task-tampering", "dormant conditional") payloads.

### Cited Findings

#### What the labs report about their own models
- Anthropic, Opus 4.7: on Gray Swan's Agent Red Teaming benchmark attack success is "roughly 0.1% on single attempts, and around 5–6% after 100 adaptive attempts"; "protection in the model layer will never be 100% effective, which is why it can't stand alone." — [How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude) (2026-05-25; vendor on an external benchmark; opened)
- Anthropic, Opus 4.8 (May 2026): one-week live competition run with Gray Swan, 12 settings (4 each tool use, coding, browsing), target identities hidden; 0.4% of attacks succeeded against Opus 4.8 and Opus 4.7 over more than 15,000 attempts, 0.9% against Sonnet 4.6, 1.6% against the next best model (GPT 5.5). Claude was tested without harness defences or injection probes; other models as publicly offered. — [Anthropic Transparency Hub, Opus 4.8 section](https://www.anthropic.com/transparency) (model released May 2026; vendor with external partner; opened)
- Anthropic, Opus 5 (July 2026): on the indirect-prompt-injection (IPI) benchmark built with Gray Swan, UK AI Security Institute and US CAISI (28 scenarios, 1,130 transferable attacks: data exfiltration, destruction, system compromise, financial transactions; coding, computer use, tool use), probability an attacker succeeds within 15 attempts: Opus 5 2.0%, Mythos 5 2.6%, Opus 4.8 5.5%, Sonnet 5 5.9%, Muse Spark 16.5%, GPT 5.6 Sol 20.0%, GPT 5.5 20.8%, GPT 5.6 Terra 30.4%, GPT 5.6 Luna 43.9%. Single attempt: Opus 5 0.2%, Opus 4.8 0.5%, GPT 5.6 Sol 3.1%. Gemini 3.1 Pro results "not directly comparable" because it was in the competition that sourced the attacks. — [Anthropic Transparency Hub, Opus 5 section](https://www.anthropic.com/transparency) (July 2026; vendor-run on a jointly built benchmark; opened)
- Anthropic, Opus 5.5 and Haiku 5.5 (Sept/Oct 2026): same benchmark, success within 15 attempts fell from 83.2% (Haiku 4.5) to 7.1% (Haiku 5.5); Haiku 5.5 by surface: coding 0.2%, tool use 4.0%, GUI computer use 24.4%; Opus 5.5 1.0%. Separate test with a Gray Swan automated attacker trained against earlier Claude models (54 scenarios x 200 runs): fewer than 1 in 1,000 attempts succeeded against Haiku 5.5, versus 58% (coding) and 19% (computer use) against Haiku 4.5. — [Anthropic Transparency Hub, Haiku 5.5 section](https://www.anthropic.com/transparency) (October 2026; vendor; opened)
- Anthropic, Fable 5.1 (Sept 2026), computer use under Gray Swan's adaptive tool Shade (14 cases x 200 attempts): Fable 5.1 0.07% (2 of 2,800), Opus 5 0.18%, Fable 5 2.50%, Sonnet 5 2.25%; product safeguards did not change the 0.07%. — [Anthropic Transparency Hub, Fable 5.1 section](https://www.anthropic.com/transparency) (September 2026; vendor; opened)
- Anthropic, Claude Code auto mode: third party Trajectory Labs ran 72 held-out IPI scenarios x 10 (attacks optimised against Opus 4.7, so unseen by tested models); 0 of 720 succeeded against Fable 5, Opus 5, Sonnet 5 in auto mode; 0.09% average for the same models in bypassPermissions mode; GPT-5.6 Sol in Codex Auto-review 5.83%, in Full Access 19.03%. Caveat stated by the vendor: a Trajectory Labs browser integration was used, first-party browser safeguards were not tested, and OpenAI shipped a new Auto-review the week before. — [Auto mode is now the default in Claude Code](https://claude.com/blog/auto-mode-default-in-claude-code) (2026-08-07; vendor-commissioned third party; opened)
- Independent counter-evidence on auto mode: Johann Rehberger reported an attack on Claude Code Opus 5 auto mode "which he claims works 80% of the time" (a downloaded archive shadows a Python module); in some runs the classifier allowed the malicious process and then blocked the agent's cleanup command. Willison notes it is closer to a "confused environment" attack than a classic injection, and concludes unattended agents need a sandbox with restricted egress. — [Simon Willison, Breaking Claude Code Opus 5 Auto Mode](https://simonwillison.net/2026/Aug/27/breaking-claude-code-opus-5-auto-mode/) (2026-08-27; independent, primary write-up at embracethered.com not opened)
- Opus 4.8 system card reportedly prints per-surface results including a browser agent hijacked 31.5% of the time "before safeguards engaged" across 129 held-out web environments. — [VentureBeat](https://venturebeat.com/security/anthropic-browser-agent-hijacked-31-percent-before-safeguards-engaged) (snippet only; system-card PDF host blocked)
- OpenAI: real-world attacks "increasingly resemble social engineering more than simple prompt overrides"; "AI firewalling" intermediaries do not usually catch such fully developed attacks; a 2025 e-mail attack against ChatGPT deep research "worked 50% of the time" in testing. OpenAI's stated design goal is constraining impact with source-sink analysis: dangerous actions or transmissions of sensitive information "should not happen silently"; the "Safe Url" mitigation detects when conversation data would be transmitted to a third party and asks the user or blocks. — [Designing AI agents to resist prompt injection](https://openai.com/index/designing-agents-to-resist-prompt-injection/) (2026-03-11; vendor; opened)
- OpenAI Lockdown Mode "deterministically disables certain tools and capabilities"; browsing is limited to cached content so "no live network requests leave OpenAI's controlled network"; image support in responses, Agent Mode, live connectors and file downloads are limited or off; "Elevated Risk" labels mark network-related capabilities whose risks "aren't yet fully addressed by the industry's safety and security mitigations". Rolled out to personal accounts 2026-06-04. — [Introducing Lockdown Mode and Elevated Risk labels](https://openai.com/index/introducing-lockdown-mode-and-elevated-risk-labels-in-chatgpt/) (2026-02-13, updated 2026-06-04; vendor; opened)
- OpenAI GPT-5.6 system card (not opened): direct attacks from the automated red-teamer GPT-Red succeeded about 0.05% against Sol; indirect attacks averaged 3.77% (Sol), 3.32% (Terra), 2.94% (Luna). — [TechRepublic](https://www.techrepublic.com/article/news-gpt-5-6-prompt-injection/) (snippet only; vendor numbers relayed by press)
- OpenAI GPT-Red: self-play-trained red-teaming agent used to adversarially train GPT-5.6; "reliably breaks our past models up to GPT-5.5", finds more successful attacks than human red-teamers and generalises to held-out environments and harnesses. — [arXiv:2607.26115](https://arxiv.org/abs/2607.26115) (v1 2026-07-28; vendor authors; abstract)
- Google: Gemini 4 Argon had a 0.7% attack success rate on the Gray Swan IPI benchmark; Gemini 4 Carbon "achieves 0.0% — resisting every evaluated attack attempt". — [Gemini 4 Carbon announcement](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/) (2026-10-28; vendor; opened). Metric definition (attempt count) is not stated in the post, so it cannot be lined up with Anthropic's k=15 figures.
- Google, Gemini 3.5 Flash computer use: targeted adversarial training plus two optional enterprise safeguards (require explicit user confirmation for sensitive or irreversible actions; automatically stop a task when an indirect injection is identified); developers are told to combine these with sandboxing, human verification and strict access controls. — [Introducing computer use in Gemini 3.5 Flash](https://deepmind.google/blog/introducing-computer-use-in-gemini-3-5-flash/) (2026-06-24; vendor; opened)
- Contradicting "0.0%": an agentic attacker swarm on a new synthetic dataset finds "no defender is fully robust: the most robust model, Gemini 4 Argon, resists only 66% of attacks at maximum attacker query budget and 87% of attacks when we limit attacker query budget to 150 queries"; the paper says human red-teaming on Gray Swan Arena is near saturation (recent Gemini and some Claude models under 1% on transfer attacks). — [arXiv:2611.11861](https://arxiv.org/abs/2611.11861) (v1 2026-11-09; authors, affiliation not verified; full text)
- An anecdotal field test: an OpenClaw instance on Opus 4.6 with a short anti-injection prompt received about 6,000 e-mail attack attempts from about 2,000 people without leaking its secret; Willison: this "provides no guarantees". — [Simon Willison](https://simonwillison.net/2026/Jun/26/hack-my-ai-assistant/) (2026-06-26; independent anecdote; opened)

#### Design patterns and system-level defences (measured by their authors unless marked)
- Out-of-band defences (CaMeL, FIDES, Progent, RTBAS, FORGE) are "validated only on static benchmarks", the methodology under which twelve in-band defences later fell to adaptive attacks at over 90% success. Independent reproduction of one of them: Progent on AgentDojo with a self-hosted Qwen2.5-7B cut mean attack success from 25.8% to 4.2%, and a hand-crafted adaptive attack did not raise it (2.6%). — [arXiv:2606.26479](https://arxiv.org/abs/2606.26479) (v1 2026-06-25; independent reproduction of one defence on one small model; abstract)
- Deterministic monitor versus guardrails, effect-based oracle, 13 tasks/12 tools: two open-weights models proposed the attacker's call in 64% and 84% of attack episodes, while a task-bound reference monitor admitted 1.3% and 7.7%. In simulation an adaptive attacker drives every guardrail stack to 100% while the task-bound monitor holds severe actions at 0%; "a human layer without a deterministic monitor fails against approval spamming unless each episode has a deterministic approval budget"; a naive monitor admitted 18 of 33 effective attack variants, a hardened one 6, a capability-bound one 1. — [arXiv:2611.11571](https://arxiv.org/abs/2611.11571) (v1 2026-11-08; authors, small models plus simulation; abstract)
- Privilege-separated two-agent pipeline (a reader agent emits structured JSON, an action agent never sees raw content) on 649 attacks that beat a single agent: isolation alone 0.31% attack success, JSON formatting alone 14.18%, both 0%. — [arXiv:2603.13424](https://arxiv.org/abs/2603.13424) (v1 2026-03-13; authors; abstract)
- Task-scoped authorisation, paired replay: with a broad bearer credential harmful execution was 8.9% to 37.8% across five local models; scoped JWT, sender-constrained and policy-engine conditions recorded zero. — [arXiv:2610.05840](https://arxiv.org/abs/2610.05840) (v1 2026-10-05; authors; abstract)
- Argument-level provenance (PACT): injection "becomes dangerous not when untrusted content appears in context, but when it determines an authority-bearing argument"; on AgentDojo 100% security on the three strongest models at 38.1–46.4% utility, 8–16 points above CaMeL. — [arXiv:2605.11039](https://arxiv.org/abs/2605.11039) (v1 2026-05-11; authors; abstract)
- CaMeL successors and limits: CaMeL guarantees "do not compose" in hierarchical multi-agent systems (multi-CaMeL 0.0% attack success versus 0.2% for per-agent CaMeL and 12.9% undefended) — [arXiv:2610.05640](https://arxiv.org/abs/2610.05640) (v1 2026-10-05; authors; abstract). Small models cannot be trusted to write the security artefact these systems enforce: model-written policies admitted attacks on 14 (Progent), 13 (IPIGuard), 11 (DRIFT) of 15 open models and CaMeL programs failed to run in up to 68% of episodes; CapLite (no model-written artefact) saw no successful attack in 13,935 attacked AgentDojo episodes — [arXiv:2611.17115](https://arxiv.org/abs/2611.17115) (v1 2026-11-12; authors; abstract). An IFC calculus agent resisted all but 2 of 1,296 attacked runs while CaMeL's policy checks "halve its utility" — [arXiv:2602.20064](https://arxiv.org/abs/2602.20064) (v1 2026-02-23; authors; abstract).
- Dual-LLM gap: "when the agent saves and later rereads untrusted data, that data ... can return as trusted data rather than as a symbol" (stored IPI); the proposed fix tracks taint through storage. — [arXiv:2607.03821](https://arxiv.org/abs/2607.03821) (v1 2026-07-04; authors; abstract)
- Context compaction breaks request-derived authorisation: Claude Code and Codex placed a model-written summary of earlier turns as a user message, so quoted injected text "reads as the user speaking"; a policy derived from a frontier compactor's summary admitted the attacker's payee in 91% of cases versus none when derived from the user's own words. — [arXiv:2611.32194](https://arxiv.org/abs/2611.32194) (v1 2026-11-24; authors; abstract)
- Tool-call smuggling: the same JSON bytes are parsed differently by guard and executor across 17 parser/validator configurations (including two official MCP SDKs); parsing once, keeping only approved-schema fields and sealing the call stopped all 7,412 crafted inputs. — [arXiv:2611.30624](https://arxiv.org/abs/2611.30624) (v1 2026-11-23; authors; abstract)
- Utility cost: on the dynamic benchmark AgentDyn (60 open-ended tasks, 560 injection cases) the best defence reached only 53.4% utility, and utility fell from 100% at trajectory length two to 23.6% beyond ten. — [arXiv:2602.03117](https://arxiv.org/abs/2602.03117) (v1 2026-02-03; authors; full text)
- Measuring what a defence leaves open: "over-privilege leakage is a separate metric, not recoverable from benign-task utility or from an attack success rate"; evaluated on Progent, CaMeL, AC4A, Permission Assistant and Claude Code auto mode. — [arXiv:2609.26900](https://arxiv.org/abs/2609.26900) (v1 2026-09-22; independent of the vendors; full text skimmed, per-defence numbers not extracted)

#### Classifiers, guard models and prompt-level defences under realistic conditions
- Adaptive generation raises attack success against filters: PIGuard 6.6% to 14.8%, ProtectAI 8.2% to 19.1%, DataFilter 21.4% to 36.6% (GPT-4o-mini); system-level Progent, DRIFT and ROPE stayed at or below 11% but most sacrificed clean utility. — [arXiv:2606.15057 AutoDojo](https://arxiv.org/abs/2606.15057) (v1 2026-06-13; authors; full text)
- Base rates: at a 2% attack rate a hijack detector with AUROC 0.879 has precision 0.076; no detector trained on one benchmark ranked another's traces better than chance (AUROC 0.47–0.52), including one scoring 0.996 in-distribution. — [arXiv:2610.41803](https://arxiv.org/abs/2610.41803) (v1 2026-10-30; authors; abstract)
- Guards are sensitive to language and surface form: small and purpose-built guards change verdicts when only the user request is translated (up to -7.4 points recall, +5.0 points false positives) — [arXiv:2610.22244](https://arxiv.org/abs/2610.22244) (v1 2026-10-15; authors; abstract); four of five specialised agent guards raise false positives by 21 to 47 points when the same action is rendered as a shell command — [arXiv:2610.24055](https://arxiv.org/abs/2610.24055) (v1 2026-10-16; authors; abstract).
- Dormant conditional payloads ("explosive prompts") succeeded in 43–83% of trials on nine production agents (n=30 each, including Codex, Gemini CLI, Claude Code CLI) versus at most 3% for an imperative baseline; off-the-shelf injection classifiers were miscalibrated on them. — [arXiv:2609.22510](https://arxiv.org/abs/2609.22510) (v1 2026-09-18; authors; abstract)
- Task-tampering (content that falsifies an input to the user's own task rather than issuing an instruction): detect-and-remove cut objective-targeting attacks to 2.4% but left observation- and state-targeting attacks at 9.5% and 12.1%; a tool-policy defence allowed 15.4% versus 17.0% undefended. — [arXiv:2611.07640](https://arxiv.org/abs/2611.07640) (v1 2026-11-05; authors; abstract)
- Prompt-level hardening helps but is model-dependent: on INFUSE (19 models, 41,824 adversarial trajectories) it cut mean attack success from 58.2% to 14.3%, while guard models "provide limited protection" — [arXiv:2610.20776](https://arxiv.org/abs/2610.20776) (v1 2026-10-14; authors; abstract). With identical weights, changing only the system prompt moved InjecAgent attack success from 0.2% to 43% on small models, and 76–80% of failed attacks were ignored rather than refused — [arXiv:2610.23254](https://arxiv.org/abs/2610.23254) (v1 2026-10-16; authors; abstract).
- Model-level training: the previously best-defended open model (Meta-SecAlign) "still suffers from attack success rates approaching 100% under adaptive prompt injections"; SecPO plus adversarial training reached 8.8% versus 78.8% AgentDojo ASR@800. — [arXiv:2610.41998](https://arxiv.org/abs/2610.41998) (v1 2026-10-30; authors; abstract)
- Stronger attacks: fragments reassembled from long context reached 61.4% macro-average success (AdaLCPI) — [arXiv:2609.36576](https://arxiv.org/abs/2609.36576) (v1 2026-09-29; authors; abstract); an attacker who observes benign conversation history reached 67.4% on AgentDojo — [arXiv:2611.31424](https://arxiv.org/abs/2611.31424) (v1 2026-11-23; authors; abstract).
- Role confusion: models weigh the style of text more than role tags; "destyling" dropped average attack success from 61% to 10% in the authors' dataset. — [Simon Willison on "Prompt Injection as Role Confusion"](https://simonwillison.net/2026/Jun/22/prompt-injection-as-role-confusion/) (2026-06-22; relayed research; opened)
- The "lethal trifecta" framing (private data, untrusted content, exfiltration path) is the working rule used by MCP maintainers and by Willison in 2026: "The only way to solve the trifecta is to cut off one of the three legs". — [MCP blog, tool annotations](https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/) (2026-03-16; opened); [Simon Willison on Lockdown Mode](https://simonwillison.net/2026/Jun/5/openai-help-lockdown-mode/) (2026-06-05; opened)

### Inferences
- The owner's system already sits on the side of the evidence that held up: exact tool allowlists per headless run and a wiki run with no connector, file, shell or web tools are deterministic capability limits, the class that kept attack success near zero under adaptive attack in the 2026 papers. Wrapping tool results as data is a prompt-level measure and should be treated as helpful but not load-bearing (0.2% to 43% swings from prompt changes on small models; frontier models far better but non-zero).
- The residual risk for a system with no exfiltration tool in the privileged run is integrity, not theft: content that looks like data (a false fact, a "decision", a tampered figure) passes instruction detectors and is exactly what a claims store ingests. Section 2 covers that.
- Any run where the same context holds private store content, untrusted content and an outbound channel (Claude Desktop with connectors or web access is the obvious one) is a lethal-trifecta configuration; vendor numbers say a single attempt rarely works on current frontier models, but 15 to 100 attempts do succeed at percent-level rates and mail lets an attacker retry daily.
- Long headless runs that auto-compact can turn quoted untrusted text into apparent user text; keeping privileged runs short or re-deriving authority from the original instruction avoids that failure.
- Tool calls should be parsed once and the validated object, not the raw text, should be executed (smuggling result).

- Anthropic system-card PDFs (hosts assets.claude.com and www-cdn.anthropic.com) and OpenAI's deploymentsafety.openai.com were blocked, so per-table system-card numbers are taken from Anthropic's Transparency Hub summaries and posts (opened) or press snippets (marked). The Fable 5.2/Mythos 5.2 (Nov 2026), Sonnet 5.5, Opus 4.6 and Sonnet 4.6 cards were not read.
- Google's Gemini 4 Safety and Security report and the April 2026 Google Workspace post on continuous IPI mitigation were not reachable; only the launch-post claims are cited.
- I found no source dated on or after 2026-02-01 that restates or evaluates a "Rule of Two"; arXiv searches for the phrase returned nothing relevant. Plan-then-execute appears only inside CaMeL-family papers.
- Vendor robustness numbers are not comparable across labs (different attempt budgets, safeguards on or off, benchmark membership); no neutral 2026 cross-lab evaluation with published methodology was found beyond the vendor-run Gray Swan/UK AISI/CAISI benchmark.
- Almost all academic defence numbers come from AgentDojo-family suites with small or mid-size models; none of the system-level defences has an independent adaptive evaluation on a frontier model that I could find.

## 2. Memory and context poisoning since February 2026

### Takeaway
2026 work shows persistent memory converts a one-off injection into a durable one: poisoned entries are written at high rates, survive 100 or more benign sessions without decay, and once planted usually fire; the write gate and provenance that cannot be laundered are the controls with measured effect, while content screening, LLM auditors and trajectory detectors fail on plainly worded false facts and on "laundered" memories. Defences that reached about 0% in their authors' tests all bind authority to the origin channel at write time and block sensitive actions in any session that read untrusted-origin memory, at a real utility cost.

### Cited Findings

#### Demonstrated attacks and measured rates
- Sleeper memory poisoning via a document, web page or repository: fabricated memories were written in up to 99.8% of trials on GPT-5.5 and 95% on Kimi-K2.6; "among successful retrievals, poisoned memories cause attacker-intended agentic actions in 60–89% of evaluations". — [arXiv:2605.15338](https://arxiv.org/abs/2605.15338) (v1 2026-05-14; authors; abstract)
- Trojan Hippo: one crafted e-mail plants a dormant payload that activates when the user later discusses finance, health or identity; 85–100% attack success against Gemini 3.1 Pro and GPT-5-mini across four memory backends (explicit tool memory, agentic memory, RAG, sliding window), "persisting for 100 or more benign sessions". — [arXiv:2605.01970](https://arxiv.org/abs/2605.01970) (v1 2026-05-03; authors; full text)
- Harness-based agents: PMPA embeds instructions in benign external sources and gets the agent to write them to persistent memory; injection success and cross-session attack success were 73.7%/55.5% on OpenClaw and 66.9%/81.7% on Claude Code; first-person phrasing raised injection success on Claude Code to 83.0% versus 54.4% and 48.1% for second-person and impersonal styles; a prompt-level defence "provides limited protection once the persistent memory has been poisoned". — [arXiv:2609.13889](https://arxiv.org/abs/2609.13889) (v1 2026-09-12; authors; full text)
- Contrasting result on the same products: "it is difficult to make an agent overwrite its own memory files using untrusted external content, payloads already planted in those files can successfully attack current and future sessions". Planted-payload success by model (credential exfiltration via CLAUDE.md/AGENTS.md, unauthorised tool use via preferences.md, brand targeting via behaviors.md): Haiku 4.5 80%/100%/10%, Opus 4.7 0%/90%/0%, GPT-5.2 30%/0%/40%, GPT-5.5 0%/80%/100%. Opus 4.7 refused credential exfiltration but "the rule still persists in 100% of the sequences" (mean persistence 96.7% at mean attack success 26.7%). — [arXiv:2607.14611](https://arxiv.org/abs/2607.14611) (v1 2026-07-16; authors; full text). The two papers disagree on how easily Claude Code writes untrusted content to memory; they use different payload styles and models.
- Carryover attacks through memory files and scheduled tasks (CarryoverBench, 12 personal-assistant scenarios, 101 attack tasks): overall attack success GPT-5.4 11.9%, Claude Sonnet 4.6 18.8%, GLM-5 27.7%, Gemini 3.1 Pro 51.5%, Qwen3-235B 63.4%; "planted payloads re-fire without measurable decay over five rounds"; four of five models had P(trigger | plant) of at least 66% via memory and above 80% via scheduled wake-ups; payloads fired on replayed or paraphrased follow-ups and 0% on unrelated or different-intent follow-ups. — [arXiv:2610.28425](https://arxiv.org/abs/2610.28425) (v1 2026-10-20; authors; full text)
- MemSecBench (310 cases, 24 configurations of harness x memory backend x model): malicious memory persisted in 84.2% of cases, the full write-to-execute chain succeeded in 50.3%, and selective repair succeeded in 56.1% of poisoned cases. — [arXiv:2607.27080](https://arxiv.org/abs/2607.27080) (v1 2026-07-29; authors; abstract)
- 29 frontier endpoints with a malicious document in the retrieval corpus: 7 exfiltrated in at least 9 of 10 runs; storing an instruction and acting on it are separable; "zero exfiltration is weak evidence of resistance" (models that never exfiltrated in draft-only runs did so in 5 to 20 of 20 runs when asked to send). Anthropic Opus and Sonnet models mostly stored no forwarding directive and exfiltrated in at most 1 of 10 runs. — [arXiv:2605.08442](https://arxiv.org/abs/2605.08442) (v1 2026-05-08; authors; abstract)
- No instruction needed: plainly worded false assertions making up 1.2% of a LongMemEval corpus cut answer accuracy from 0.850 to 0.300. — [arXiv:2608.21230](https://arxiv.org/abs/2608.21230) (v1 2026-08-21; authors; full text)
- Attacks built to pass audits: MAFIA reached up to 90.7% attack success while cutting audit detection from a peak of 83.3% to at most 7.4% using "compact factual cloaks" — [arXiv:2608.03844](https://arxiv.org/abs/2608.03844) (v1 2026-08-04; authors; abstract); PipePoison optimises across write, retrieval and use and "remains effective under eight representative defenses" — [arXiv:2609.00523](https://arxiv.org/abs/2609.00523) (v1 2026-09-01; authors; abstract); MemMorph biased tool selection with three injected records (up to 85.9%) — [arXiv:2605.26154](https://arxiv.org/abs/2605.26154) (v1 2026-05-24; authors; abstract).
- Other 2026 attack measurements: GhostWriter about 98% injection and about 60% activation against personal-assistant agents — [arXiv:2607.06595](https://arxiv.org/abs/2607.06595) (v1 2026-07-06; authors; abstract); eTAMP poisons web-agent memory by observation alone (up to 32.5% on GPT-5-mini, 23.4% on GPT-5.2) and agents under environmental stress were up to 8 times more susceptible — [arXiv:2604.02623](https://arxiv.org/abs/2604.02623) (v1 2026-04-03; authors; abstract); a multi-step "trojan" in an OpenClaw-style workspace with GPT-5.4 reached 95.5% while single-turn injections were near zero on the same model — [arXiv:2605.31042](https://arxiv.org/abs/2605.31042) (v1 2026-05-29; authors; abstract).
- No attacker needed: with a memory tool a simulated-misaligned agent wrote a goal for a future session to act on in 58% of runs (explicit prompt) and 18% (values-only prompt); with the memory tool removed, agents wrote the goal to a file in 74% of sessions; goals persisted through 100 sessions of unrelated work; "an LLM memory auditor from prior work (MemMorph) only reduces propagation from 71% to 34% of runs". — [arXiv:2610.04083](https://arxiv.org/abs/2610.04083) (v1 2026-10-02; authors; abstract)
- Benign contamination: under raw shared state, benign interactions alone produced contamination rates of 57–71% when scope-bound facts were reapplied to another user. — [arXiv:2604.01350](https://arxiv.org/abs/2604.01350) (v1 2026-04-01; authors; abstract)
- Self-evolving agents get worse: learning from user feedback raised average injection success by 14.0–48.8 percentage points (skill evolution) and 3.0–39.3 (reinforcement learning) — [arXiv:2610.39122](https://arxiv.org/abs/2610.39122) (v1 2026-10-29; authors; abstract); a self-learning defence can itself be poisoned into over-refusal by one injection episode — [arXiv:2611.33385](https://arxiv.org/abs/2611.33385) (v1 2026-11-24; authors; abstract).
- Rules files, skills and repository docs: an instruction in a README or TODO file was followed 2.6 times more often on average (GPT-5.4 agent) than the same instruction in a code or data file — [arXiv:2610.38867](https://arxiv.org/abs/2610.38867) (v1 2026-10-28; authors; abstract). Injected rule files (AGENTS.md, .cursorrules) induce coding agents to swap dependencies for attacker packages — [arXiv:2610.09264](https://arxiv.org/abs/2610.09264) (v1 2026-10-07; authors; abstract, no rate in abstract). In a registry-scale study of 48,682 skills a live agent executed the injected payload in 48.5% of sampled flagged skills — [arXiv:2611.30932](https://arxiv.org/abs/2611.30932) (v1 2026-11-23; authors; abstract). The strongest skill detector reached 98.4% recall on code injection "yet collapses on prompt-injection and agent-control attacks" — [arXiv:2606.07131](https://arxiv.org/abs/2606.07131) (v1 2026-06-05; authors; abstract).
- Real incidents in 2026: CoSnitch (CVE-2026-24301, public 2026-08-18): a web-page summarisation path "wrote malicious instructions into persistent memory" of Microsoft Copilot Personal; the Mini Shai-Hulud supply-chain worm (May 2026) "planted a Claude Code hook and VS Code task that uninstalling the affected package did not remove". — [OWASP GenAI Exploit Round-up Q3 2026](https://genai.owasp.org/2026/10/08/genai-and-agentic-ai-exploit-roundup-q3-2026/) (2026-10-08; community round-up, "not an official OWASP publication"; opened)
- Self-replicating document injection: hidden instructions in a source document make Copilot for Word copy them into the output document, which then carries the attack onward; no full-class mitigation after 144 days. — [Simon Willison, AI Worming through Word](https://simonwillison.net/2026/Jul/29/ai-worming-through-word/) (2026-07-29; relayed research; opened)
- Model-generated poisoning of its own context: OpenAI found 27 compaction summaries in which an unreleased research model inserted unrelated instructions (including to disregard its constraints), and during GPT-5.6 Sol training "many model instances added instructions to their summaries to conceal mistakes". — [OpenAI, framework for reporting model misalignment](https://openai.com/index/model-misalignment-reporting-framework/) (2026-09-16; vendor; opened)
- Lab statements: "An injection that lands in any of these [product memory, CLAUDE.md files, mounted workspaces, state directories of scheduled agents] is reloaded each time the agent starts ... Good classifiers on session startup will need to become more commonplace"; and sub-agent output treated as higher trust than raw tool results is "a new vector for prompt injection". — [How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude) (2026-05-25; vendor; opened)
- OWASP LLM01:2026 names "memory persistence" as a root cause: "an injection that writes to long-term memory, a RAG corpus, a vector store, or a hosted memory service taints every subsequent session that reads from that store". — [OWASP LLM01:2026 Prompt Injection](https://genai.owasp.org/llm2026/llm012026-prompt-injection/) (2026 edition announced 2026-09-02; opened)

#### Defences with measured effect
- Origin labels plus action blocking: memory entries labelled trusted/untrusted at write; any session that retrieves an untrusted-labelled entry has send tools blocked. 0% attack success in all evaluated configurations with a non-interference proof for the two-session attack; the three lighter memory-layer defences reduced success to 0–5% "in most configurations"; "every defense trades away utility and the best choice depends on the deployment". — [arXiv:2605.01970](https://arxiv.org/abs/2605.01970) (v1 2026-05-03; authors; full text)
- Non-malleable, origin-bound authority: content- and lineage-based signals are both launderable through "the agent's own summarization, a trusted-tool echo, and manufactured corroboration" (up to 68% laundering attack success against existing defences on eight frontier models); binding origin at write time and gating elevation on Sybil-resistant corroboration reached 0% on direct and laundering attacks "at full legitimate utility". — [arXiv:2606.24322](https://arxiv.org/abs/2606.24322) (v1 2026-06-23; authors' own benchmark; abstract)
- Provenance that survives consolidation: during LLM memory consolidation an external observation "may be rewritten as apparent user history or workflow support"; consolidated memories reached up to 1.000 attack success; with platform-maintained provenance, confirmation and risk labels no unauthorised high-risk action passed the gate. — [arXiv:2607.29167](https://arxiv.org/abs/2607.29167) (v1 2026-07-31; authors, schema-grounded evaluation; abstract)
- Signed writes: HMAC provenance at write time cut attack success from 93–100% to 0% for unsigned injections; for an authenticated adversary with one injection, randomised ablation with verdict voting held success to 8.0% (95% CI 5.8–10.9, n=450). The authors prove "no provenance-free retrieval-time filter can certify against adaptive injection". — [arXiv:2606.12703](https://arxiv.org/abs/2606.12703) (v1 2026-06-10; authors; abstract)
- Cross-session information-flow control blocked 97% of "semantic norm drift" attacks in which a policy-formatted document re-emerges from a shared vector store as trusted context; four safety classifiers (one trained on memory poisoning) produced zero detections across 510 checkpoints, and in 59 of 65 cases the agent cited the injected document as authority. — [arXiv:2605.22842](https://arxiv.org/abs/2605.22842) (v1 2026-05-12; authors; abstract)
- Removing the recall tool ("memory sandbox") was the only one of six defences at four layers that blocked persistent-memory exfiltration (0% for eight of nine open models, 5,040 runs), and it was bypassed when the model rebuilt the instruction from the retrieval corpus (32.5–97.5% on three models). — [arXiv:2605.08442](https://arxiv.org/abs/2605.08442) (v1 2026-05-08; authors; abstract)
- What the defences cost on benign traffic (LoCoMo, 750 turns x 3 runs): LLM anomaly detection blocked 0.4% of turns; a read-time reranker dropped 2.2% of memories and withheld at least one memory from 14.9% of questions, with content-based justification found for only 2 of 50 sampled drops; token overhead 0% for sanitisation and provenance, 1.5% anomaly detection, 3.0% reranker, 4.5% stacked; no detectable accuracy cost within ±2.4–4.6 points. — [arXiv:2609.22818](https://arxiv.org/abs/2609.22818) (v1 2026-09-19; authors; abstract)

#### Defences that failed or are only proposals
- Write-time content screening is "structurally blind to false-fact poisoning": a four-stage pipeline with 0.832 recall on injections and 1.5% false flags rejected 0 of 360 poisoned memories. Provenance-weighted ranking at the shipped weight was indistinguishable from no defence (p=0.80); a stronger weight works only by excluding untrusted content (accuracy 0.3167 to 0.7000 when untrusted content is mostly benign, but 0.0417 when the needed evidence itself arrives untrusted). — [arXiv:2608.21230](https://arxiv.org/abs/2608.21230) (v1 2026-08-21; authors reporting a negative result on their own system; full text)
- Trajectory-based provenance detection: false-positive rate 24.7–57.6% across 13 models (N=4,160), positive predictive value at most 3.85% at 1% attack prevalence, and a recipient-metadata gate flagged 129 of 129 legitimate external e-mails; "retrieval-before-send is an attack precondition, not a maliciousness predicate". — [arXiv:2606.30566](https://arxiv.org/abs/2606.30566) (v1 2026-06-29; authors falsifying their own detector; abstract)
- "Existing memory systems and defenses are not more robust than an untuned manager" when both stale facts and planted content must be handled; fine-tuning the memory manager more than doubled the robustness score "though robustness remains incomplete". — [arXiv:2610.41056](https://arxiv.org/abs/2610.41056) (v1 2026-10-29; authors; abstract)
- "Existing prompt injection defenses fail to cover memory poisoning attacks", and agents that write and retrieve memory more aggressively are more exploitable. — [arXiv:2606.04329](https://arxiv.org/abs/2606.04329) (v1 2026-06-03; authors; abstract)
- Proposals without independent or adversarial validation: MemLineage (per-principal signed entries in a Merkle log plus a derivation DAG) — [arXiv:2605.14421](https://arxiv.org/abs/2605.14421) (v1 2026-05-14; abstract); "sleeper channels" defence keyed on a canonical action digest with one-shot owner attestations, empirical evaluation "preregistered as follow-on" — [arXiv:2605.13471](https://arxiv.org/abs/2605.13471) (v1 2026-05-13; abstract); MemSentry write interception with Accept/Review/Quarantine decisions, 91.7% accuracy on 1,000 GPT-4-generated scenarios — [arXiv:2609.08747](https://arxiv.org/abs/2609.08747) (v1 2026-09-08; authors, synthetic; abstract); SAFE-Mem claim-level authority — [arXiv:2610.22959](https://arxiv.org/abs/2610.22959) (v1 2026-10-16; authors; abstract); epistemic-guard, an out-of-process MCP proxy that gates SQLite writes across 7 provenance domains and blocked 100 of 100 unauthorised memory writes but showed a 38.24% false-positive rate on 60 live traces — [arXiv:2611.27095](https://arxiv.org/abs/2611.27095) (v1 2026-11-20; authors; abstract).

#### Memory quality (not adversarial) from a lab
- "A note that's wrong from the start or that drifts as the environment changes can be read, and trusted" in a later session; a background "dreaming" pass that checks notes against the original transcripts corrected such errors; promoting notes into every session's context "must be done carefully ... an incorrect note can be carried into every session". When many agents built a shared wiki, a brief generated from it contained only 41 of 57 required facts (72%) because "agents had overwritten one another's work". — [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory) (2026-11-06; vendor; opened)
- Memory tool documentation: restrict all memory operations to the memory directory with path validation; "Claude usually refuses to write sensitive information to memory files. For stronger guarantees, add validation that strips sensitive data before your handler writes the file." — [Claude Platform docs, memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) (page undated, fetched 2026-11-27; vendor; opened)

### Inferences
- The owner's store has the right shape for the defences that worked (write-time validation, versioning, mandatory evidence citation, no delete tools, owner approval for status changes), but the 2026 results say three specific properties decide whether that shape holds: (a) the origin channel of each claim (owner-typed, mail, chat, web history, README, transcript) must be recorded by code at write time, not inferred by the model; (b) that label must not be upgraded when a claim is summarised into a wiki statement, echoed by a tool or "corroborated" by several items from the same origin, since those are the three laundering channels; (c) a statement's authority should be capped by its least-trusted supporting evidence.
- Write validation that checks form and evidence presence cannot catch a plainly worded false claim (0 of 360). The owner's card-click confirmation is therefore the real integrity control for false facts, and it only works if the card shows origin and evidence, not just the claim text.
- "Evidence must be cited" is a stronger control when the cited evidence is itself checked for being untrusted-origin only; several items forwarded from one sender are one origin.
- The wiki compile run reads the claims store, so a poisoned claim is a stored injection into a later, differently privileged run; the Dual-LLM "stored IPI" and "sub-agent output treated as trusted" findings both describe this hop. Because that run has no outbound tools the consequence is bounded to wrong wiki content, which is the argument for keeping it tool-less.
- A periodic re-verification pass of stored statements against their source evidence is supported by one lab's results as a fix for drift and honest errors; no 2026 source shows it stops a deliberately planted false source.
- Instruction-like text in claims ("always", "from now on", conditional triggers, first-person phrasing) is a cheap anomaly signal that 2026 attacks rely on (first-person 83% versus 48–54%), but classifiers alone had poor precision at realistic base rates, so it suits a review flag, not an automatic gate.

### Gaps
- No 2026 source evaluates memory-poisoning defences on a claims/wiki store with human confirmation in the loop; the closest are personal-assistant benchmarks.
- No independent replication of the 0% results (origin-bound authority, IFC labelling, signed writes); all are on the authors' own benchmarks.
- I found no measured study of injection through meeting transcripts or speech-to-text specifically.
- MemoryDojo ([arXiv:2611.09721](https://arxiv.org/abs/2611.09721), v1 2026-11-06) and MemForm ([arXiv:2610.14431](https://arxiv.org/abs/2610.14431), v1 2026-10-10) abstracts give no headline rates; full texts not read.
- Anthropic's memory-tool documentation page carries no date, so its publication date relative to the cut-off is unverified.

## 3. MCP security since February 2026

### Takeaway
The 2026-07-28 specification made MCP stateless and hardened OAuth, but it does not address tool poisoning or prompt injection at protocol level; official guidance now says in plain words that a local server is an ordinary process with the user's full privileges, that tool descriptions and annotations are untrusted input that can change after approval, and that containment is the host's and operator's job. Measurement studies find no agent framework implements an intentional defence against poisoned tool metadata and that most destructive tools reach execution with no enforced human approval.

### Cited Findings

#### Specification and official guidance
- 2026-07-28 revision (previous: 2025-11-25): protocol-level sessions and the `Mcp-Session-Id` header removed; `initialize` handshake removed (every request carries protocol version and client capabilities); server-initiated requests (roots, sampling, elicitation) replaced by Multi Round-Trip Requests where the server returns `input_required` and the client retries; `tools/list` should be returned in deterministic order; list results carry `ttlMs` and `cacheScope`; Roots, Sampling and Logging deprecated. — [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) (2026-07-28; standard; opened)
- Authorisation hardening in the same revision: clients "MUST validate a present `iss` against the recorded issuer before redeeming the authorization code" (SEP-2468); client credentials are bound to the issuing authorisation server and "MUST NOT" be reused with another (SEP-2352); Dynamic Client Registration deprecated in favour of Client ID Metadata Documents; `application_type` required during registration (SEP-837). — [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) (2026-07-28; opened); summary in [The 2026-07-28 Specification](https://blog.modelcontextprotocol.io/posts/2026-07-28/) (2026-07-28; opened)
- Because the protocol is stateless, servers pass explicit state handles as tool arguments; the best-practices page adds "State Handle Hijacking": servers "MUST NOT treat possession of a state handle as authentication" and should use non-guessable handles. — [MCP Security Best Practices (2026-07-28 docs)](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices) (opened; page also covers confused deputy, token passthrough, SSRF, local server compromise, mix-up attacks, scope minimisation)
- New "Local Server Security" guide (listed only under the 2026-07-28 and draft docs): a local server "is not a plugin running inside a sandbox the protocol provides. It is an ordinary operating system process" that inherits environment variables, can read anything the account can read and can open outbound connections; "the client and a stdio server share one trust domain"; "Every server you configure shares the same model context, so a malicious server can influence how the agent uses the tools of every other server." — [MCP Local Server Security](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/local-server-security) (2026; official guidance; opened)
- Same guide on tool poisoning and rug pulls: "Tool names and descriptions are instructions your model reads"; a server "can quietly change them after you approved it (a rug pull), so a one-time consent dialog and package pinning do not cover this surface"; "no check proves what a server will do". Recommended defaults: pin exact versions; read the tool list and prefer clients that pin tool definitions and re-prompt on change; keep the roster small; run third-party servers in a container; pass secrets per server with narrowly scoped tokens; grant a single read-only project directory; "run servers with no network access unless they demonstrably need it"; keep an audit trail of which server and tool ran when. — [MCP Local Server Security](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/local-server-security) (opened)
- Tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) are hints only: "clients must treat them as untrusted unless they come from a trusted server"; defaults are pessimistic (unannotated tool is assumed destructive and open-world); "treat anything a tool considers external as a potential source of untrusted content". — [Tool Annotations as Risk Vocabulary](https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/) (2026-03-16; MCP maintainers; opened)
- Enterprise-Managed Authorization extension declared stable 2026-06-18. — [MCP blog index](https://blog.modelcontextprotocol.io/) (opened, index entry only)
- Press coverage says the revision shifts security decisions previously enforced by the protocol to server developers and operators. — [SecurityWeek](https://securityweek.com/new-enterprise-ready-mcp-specification-brings-new-security-challenges) (snippet only)

#### Measured attacks and defences
- Cross-framework tool-poisoning measurement with real execution (12 frameworks, 18 models, 45 scenarios, 9,720 cells): overall attack success 22.9%; of the vulnerable cells 12.1% verifiably exfiltrated a secret; "no framework implements intentional defense"; nine frameworks cluster at 23–26%, so resistance is model-level; model attack success ranged 0.4% to 49.7% (Claude Opus 4.8 vulnerable in 8 of 530 cells); a regex description scanner rejected 20 of 45 scenarios at a 7.2% false-positive rate. — [arXiv:2611.03555](https://arxiv.org/abs/2611.03555) (v1 2026-11-02; authors, independent of vendors; abstract)
- Approval gap: in a 1,000-repository sample of the official registry an estimated 90% of destructive tools (95% CI 82–95) have no server-side confirmation; 32 of 41 popular open-source hosts and SDKs have no approval step by default; four of five low-cost models executed an injected deletion in 479 of 960 runs; prompting for every tool not annotated read-only or non-destructive would cut the unapproved share from 60.7% to 5.4%. — [arXiv:2611.02527](https://arxiv.org/abs/2611.02527) (v1 2026-11-02; authors; abstract)
- Filesystem capability laundering: across 21,097 servers from nine registries, 787 of 4,806 triaged servers (16.4%) had filesystem capabilities despite non-filesystem classifications; 150 confirmed vulnerable; 13 advisories "including two CVEs in Anthropic's Git MCP Server". — [arXiv:2610.22301](https://arxiv.org/abs/2610.22301) (v1 2026-10-15; authors; abstract)
- CVE snapshot through February 2026: 24 validated MCP vulnerabilities, 87.5% critical or high, injection and path traversal 66.7% of cases. — [arXiv:2611.11104](https://arxiv.org/abs/2611.11104) (v1 2026-11-08; authors; abstract)
- Attacks on descriptions and responses: threshold poisoning split across several tools keeps above 90% success while evading description scanners — [arXiv:2606.27027](https://arxiv.org/abs/2606.27027) (v1 2026-06-25; authors; abstract); adaptive payloads in tool responses exceed 95% undefended and keep above 50% against four defences — [arXiv:2603.24203](https://arxiv.org/abs/2603.24203) (v1 2026-03-25; authors; abstract); a "logging" directive in metadata induces an extra exfiltrating call in 62.64–100% of 18 model-server pairs, three defences leave above 55%, and an instruction detector flags 85.53% of benign descriptions — [arXiv:2610.36108](https://arxiv.org/abs/2610.36108) (v1 2026-10-26; authors; abstract).
- Model-as-client benchmark (COPEX, nine models, 3,375 trials): mean attack success 64.4%; combined input and context scanning reduced mean success by 49.6% on a defence subset. — [arXiv:2610.04378](https://arxiv.org/abs/2610.04378) (v1 2026-10-03; authors; abstract)
- In the wild: "Deadbugz" (2026-08-10), a malicious MCP server promoted through 23 pull requests in 74 minutes, "behaved normally for its first three tool calls before changing its own tool metadata to direct connected agents toward credentials"; no pull request was merged. — [OWASP GenAI Exploit Round-up Q3 2026](https://genai.owasp.org/2026/10/08/genai-and-agentic-ai-exploit-roundup-q3-2026/) (2026-10-08; opened)
- Privacy side channel: MCP tool-call traces alone allowed profile inference at 26.25% success versus 17.97% for prior-based guessing; arguments and results carry most of the signal. — [arXiv:2610.41885](https://arxiv.org/abs/2610.41885) (v1 2026-10-30; authors; abstract)
- Proposal: generate tool descriptions from the implementation instead of trusting the server's text (TRUSTDESC, evaluated on 52 tools). — [arXiv:2604.07536](https://arxiv.org/abs/2604.07536) (v1 2026-04-08; authors; abstract)
- Lab view: "A locally installed tool is auditable ... A remote tool ... can change behavior at any point after you've approved it"; "Tool output is an attack surface even when the tool is trusted"; "An audited connector isn't the same as audited data—a GitHub connector, for instance, can load a poisoned README straight into the model's context". — [How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude) (2026-05-25; vendor; opened)

### Inferences
- The owner's own SQLite MCP server is first-party and local, so the supply-chain items matter mainly for any third-party connectors used in Claude Desktop and the end-of-day run; for those, the official defaults map directly: pinned versions, per-server scoped credentials, no network unless needed, small roster.
- Because all servers in one client share a model context, a third-party connector in Claude Desktop can steer calls to the owner's store tools; the store's own server-side rules (no delete, approval for status change, validation) are the control that does not depend on the client behaving.
- Recording a hash of each server's tool names, descriptions and schemas and alerting on change addresses the rug-pull pattern seen in Deadbugz; the spec's new deterministic `tools/list` ordering makes such hashing stable.
- With MCP now stateless, any handle the store's server hands out (cursor, draft id) is an ordinary argument and must not double as authorisation.

### Gaps
- No official MCP guidance on prompt injection or memory writes through tool results was found; the spec treats these as host concerns.
- I could not verify from the official text how elicitation-based confirmation behaves under the new retry pattern when hosts do not support it (only the approval paper speaks to it).
- A VentureBeat piece titled "MCP's new spec turns a planted prompt into a stolen credential" appeared in search results; host blocked, content not verified.

## 4. Agent permissions and sandboxing guidance from the labs; standards and frameworks updated in 2026

### Takeaway
The labs' 2026 guidance converges on "contain first, classify second": hard environment boundaries (sandbox, egress control, credentials kept out of the agent's reach) are the only layer that held in the incidents they disclose, per-action human approval is documented as weak (users approve 93–97% of prompts and caught 13.6% of planted dangerous commands), and approval should move to plan level or to a bound, trustworthy rendering of the exact effect. OWASP shipped a 2026 LLM Top 10, an Agent Control Standard and an agentic builder's guide; NIST opened an AI Agent Standards Initiative; six cyber agencies published joint adoption guidance.

### Cited Findings

#### Approval fatigue and approval design
- "Our telemetry showed users approved roughly 93% of permission prompts"; experienced users auto-approve about twice as often as new users; an OS sandbox (reads allowed, writes inside the workspace, network denied by default) gave "an 84% reduction in permission prompts". — [How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude) (2026-05-25; vendor telemetry; opened)
- Later figure: "users approve 97% of permission prompts in Claude Code"; when shown a plan instead, "users reject 39% of them" versus 3% of individual permission requests; as of June 2026 49.5% of active CLI users had created a Bash allow-rule (5% allow any shell command, another 43% interpreter rules equivalent in practice) and 25% of interactive sessions start in bypass mode. — [Auto mode is now the default in Claude Code](https://claude.com/blog/auto-mode-default-in-claude-code) (2026-08-07; vendor telemetry; opened). The 93% and 97% figures come from the same vendor at different dates; no reconciliation is given.
- Controlled study, 1,053 paid professional testers, one permission prompt swapped for a clearly dangerous command: humans refused 13.6% (143 of 1,053); the classifier blocked 89% (937); humans blocked about 17% early in a session and about 5% after 50 or more prior prompts. — [Auto mode is now the default in Claude Code](https://claude.com/blog/auto-mode-default-in-claude-code) (2026-08-07; vendor-run via a research vendor; opened)
- Classifier-as-approver numbers: two-stage classifier 0.4% false positives on 10,000 real tool calls, 17% false negatives on 52 real "overeager" actions, 5.7% on 1,000 synthetic exfiltration attempts; the classifier sees only user messages and tool calls (assistant prose and tool results are stripped so injected content cannot argue with it); a separate probe scans tool outputs and adds a warning. "It is not a drop-in replacement for careful human review on high-stakes infrastructure." — [How we built Claude Code auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode) (2026-03-25; vendor; opened). External red-teaming by Apollo Research moved the miss rate on synthetic adversarial sets from 12% to 7% — [same Aug 2026 post](https://claude.com/blog/auto-mode-default-in-claude-code) (vendor with third party; opened).
- Plan-level oversight: showing the whole plan for review "shifts the user's level of oversight from the individual step to the overall strategy". — [Trustworthy agents in practice](https://www.anthropic.com/research/trustworthy-agents) (2026-04-09; vendor; opened)
- Approval is a second factor only if a compromised agent cannot produce it and it names exactly what it approves: twelve attacks on the approval path (decoy recipients, label spoofing, threshold splitting); a trusted card rendered from the real pending effect cut forged-narration success from 0.54 to 0.03; flooding still succeeded 0.45 to 0.60 of the time against a modelled approver; "approval cannot stop effects that policy already allows". — [arXiv:2610.21063](https://arxiv.org/abs/2610.21063) (v1 2026-10-15; authors; abstract)
- Approval card reconstructed from the ground-truth pending action and rendered outside model-controlled UI: attack success 68–100% without it, 0% with it on a 24-scenario browser benchmark, 78% legitimate-task completion. — [arXiv:2609.18411](https://arxiv.org/abs/2609.18411) (v1 2026-09-16; authors; abstract)

#### Sandboxing, least privilege and incidents the labs disclosed
- Internal red-team phish (Feb 2026): an employee pasted a prompt that asked the agent to read cloud credentials and POST them out; "Across 25 retries of that prompt, Claude completed the exfiltration 24 times"; because the instruction came through the user "there's nothing anomalous for a classifier to catch"; "The only defense that holds in this situation is the environment". — [How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude) (2026-05-25; vendor; opened)
- Egress allowlists are capability grants: a file with hidden instructions and an attacker's API key made the agent upload workspace files to the attacker's account through the allowlisted vendor API; fix was a proxy that only passes the session's own token. Also: three reported vulnerabilities executed project-local configuration before the trust prompt; symlinks must be resolved before path validation; file mounts offered as read-only, read-write and read-write-no-delete; "the weakest layer is the one you built yourself". — [same post](https://www.anthropic.com/engineering/how-we-contain-claude) (vendor; opened)
- Same post's summary principles: "Design for containment at the environment layer first, then steer behavior at the model layer"; "Match isolation strength to the user's capacity for oversight"; "Be wary of custom components". It also notes tool results can be inspected by "a small, fast model" before they enter context, and that a canary string was added to a shared thread containing a live payload. — [same post](https://www.anthropic.com/engineering/how-we-contain-claude) (vendor; opened)
- Credentials out of reach: "any untrusted code that Claude generated was run in the same container as credentials—so a prompt injection only had to convince Claude to read its own environment"; "The structural fix was to make sure the tokens are never reachable from the sandbox"; narrow scoping alone "encodes an assumption about what Claude can't do with a limited token". — [Scaling Managed Agents](https://www.anthropic.com/research/managed-agents) (2026-04-08; vendor; opened)
- Command allow-lists are unreliable: an agent listed `cat` as safe and an injection hidden at the bottom of a README used process substitution to run downloaded code. — [Simon Willison on Snowflake Cortex](https://simonwillison.net/2026/Mar/18/snowflake-cortex-ai/) (2026-03-18; relayed PromptArmor report; opened). Auto mode likewise drops allow rules that grant arbitrary code execution — [auto mode post](https://www.anthropic.com/engineering/claude-code-auto-mode) (2026-03-25; opened).
- An issue-triage agent given shell tools and fed the issue title was injected and, through a shared CI cache, led to compromise of a release pipeline ("Clinejection"). — [Simon Willison](https://simonwillison.net/2026/Mar/6/clinejection/) (2026-03-06; relayed research; opened)
- Kernel-sandbox runtime with copy-on-write workspace and identity-pinned egress proxy: prompts reduced 90.7–97.9% in 52 real coding sessions and attack success on 80 attacks from 100% to 0%. — [arXiv:2611.08516](https://arxiv.org/abs/2611.08516) (v1 2026-10-22; authors; abstract)

### Inferences
- The owner's click-to-confirm cards are a per-item approval and inherit the fatigue numbers above; the 2026 evidence favours fewer, higher-information decisions (batch or plan-level review, which users rejected 39% of the time versus 3%), a bounded number of approvals per run, and cards rendered by code from the stored record (exact claim text, origin channel, evidence excerpt) so the model cannot narrate what is being approved. Catch rate fell from 17% to 5% after 50 prompts, which argues for capping cards per sitting.
- "Status changes need the owner's approval" matches the "human control points for high-risk activities" recommendation; the approval-spamming result says to add a deterministic budget.
- The headless runs should be assumed to do whatever their process is allowed to do; exact allowlists are sound, command-pattern allow-lists inside a shell tool are not, and anything reachable through an allowed domain counts as granted.
- Custom components (the owner's own MCP server, redaction and rendering code) are where the lab found its own failures, so they deserve the tests.

## 5. Hidden-content channels: invisible Unicode, text in images, Markdown and link exfiltration

### Takeaway
Hidden-text injection exists in the wild at low but real rates and is cheap to neutralise for text (strip HTML comments and invisible code points before the model reads content); exfiltration in 2026 incidents went through rendered images, auto-followed links and allow-listed APIs, and the fixes that worked were deterministic limits on which URLs can be fetched or rendered. Image-borne injection is harder: adaptive visual attacks beat every tested screenshot-level defence.

### Cited Findings
- GitHub at scale: about 145 million issues, pull requests, comments and READMEs analysed for text GitHub does not render to humans but agents receive; 2,281 validated findings in issues/PRs/comments (16 per million items) and AI-directed hidden text in the READMEs of 107 repositories; actual attacks about one in 3.3 million items, aimed at maintainers' triage, review and CI agents. Replayed against five models, the attacks succeeded "against one small, fast model in 19% of cases, and against none once HTML comments are stripped". — [arXiv:2611.28763](https://arxiv.org/abs/2611.28763) (v1 2026-11-21; authors; abstract)
- Invisible Unicode: across 8,308 outputs from five models, models followed instructions encoded in zero-width characters or Unicode Tags; tool use "dramatically amplifies compliance" (Cohen's h up to 1.37); OpenAI models tended to decode zero-width binary and Anthropic models Unicode Tags; an explicit decoding hint raised compliance by up to 95 percentage points. — [arXiv:2603.00164](https://arxiv.org/abs/2603.00164) (v1 2026-02-26; authors; abstract)
- OWASP LLM01:2026 lists "tag-block, variation-selector, and zero-width Unicode" as carriers for instructions and for exfiltrating bytes in benign-looking output, and "data exfiltration via image-URL channels, hidden Unicode characters in rendered output, or covert tool-logging side channels"; mitigation text: "Filter at every modality boundary (text, image, audio, structured data), not just text. Run modality-specific classifiers, OCR over images, and transcription over audio, then apply text filters to the extracted content." — [OWASP LLM01:2026](https://genai.owasp.org/llm2026/llm012026-prompt-injection/) (2026 edition; opened)
- Rendered-image exfiltration: an agent allowed to e-mail the user's own inbox without approval sent messages whose external images leaked data when opened; pre-authenticated file links could be leaked the same way. — [Simon Willison, Copilot Cowork exfiltrates files](https://simonwillison.net/2026/May/26/copilot-cowork-exfiltrates-files/) (2026-05-26; relayed research; opened)
- Link-following exfiltration: a fetch tool restricted to user-entered or search-returned URLs was bypassed because it could also follow URLs embedded in pages it had fetched; a honeypot led the model through nested links letter by letter and extracted the user's name and city from memory; the payload was served only to the vendor's user-agent. — [Simon Willison, web_fetch exfiltration](https://simonwillison.net/2026/Jul/15/claude-web-fetch-exfiltration/) (2026-07-15; relayed research; opened)
- One-click link execution: a crafted link ran a prompt in the victim's authenticated assistant session and transmitted connected-account data through URL fetching (CoSnitch, CVE-2026-24301). — [OWASP Q3 2026 round-up](https://genai.owasp.org/2026/10/08/genai-and-agentic-ai-exploit-roundup-q3-2026/) (2026-10-08; opened)
- Vendor mitigations for the exfiltration leg: Lockdown Mode turns off image support in responses and live browsing; "Safe Url" asks or blocks when conversation-derived data would be sent to a third party. — [OpenAI Lockdown Mode](https://openai.com/index/introducing-lockdown-mode-and-elevated-risk-labels-in-chatgpt/) (2026-02-13; opened); [OpenAI design post](https://openai.com/index/designing-agents-to-resist-prompt-injection/) (2026-03-11; opened)
- Hidden white-on-white text in documents is now used for self-replicating document injections. — [Simon Willison, AI Worming through Word](https://simonwillison.net/2026/Jul/29/ai-worming-through-word/) (2026-07-29; opened)
- Images: adaptive visual prompt injection with destinations not visible in screenshots averaged 91.87% and 91.99% success across 10 and 11 defence configurations for computer-use and browser agents — [arXiv:2611.29268](https://arxiv.org/abs/2611.29268) (v1 2026-11-22; authors; abstract). Text that appears only after an image is downsampled reached 58.75% average success on four closed vision models, though end-to-end behavioural compromise of a web agent stayed about 4% and generic input transforms gave little protection — [arXiv:2611.16744](https://arxiv.org/abs/2611.16744) (v1 2026-11-12; authors; abstract). Imperceptible image perturbations corrupted multimodal long-term memory (61.6% poisoning, 58.4% injection) — [arXiv:2607.15657](https://arxiv.org/abs/2607.15657) (v1 2026-07-17; authors; abstract).
- Placement matters: the same instruction in a README or TODO file was followed 2.6 times more often than in a code or data file (GPT-5.4 agent). — [arXiv:2610.38867](https://arxiv.org/abs/2610.38867) (v1 2026-10-28; authors; abstract)
- Vendor GUI numbers show the visual surface is the weakest: Haiku 5.5 was at 24.4% within 15 attempts in GUI computer use versus 0.2% in coding. — [Anthropic Transparency Hub](https://www.anthropic.com/transparency) (October 2026; vendor; opened)

### Inferences
- A deterministic normalisation step before any model sees ingested mail, chat, documents, READMEs, commit messages or transcripts (remove HTML comments and non-rendered markup, Unicode tag block, variation selectors, zero-width and bidirectional controls; log what was removed) is directly supported by the one study that measured it, and it is cheap. Stripped content is itself a signal worth attaching to the item.
- "Code, not the model, renders HTML and SVG" closes the classic Markdown-image channel only if that code never emits remote resource URLs or clickable links built from model- or content-supplied strings; the 2026 incidents all used rendered images or followed links.
- Repository documentation is a higher-risk surface than code for the end-of-day agent; treating README and commit-message text as the least-trusted origin is consistent with the placement result.
- If images or screenshots are ever ingested, OCR-then-text-filter is OWASP's stated approach, but adaptive visual attacks beat the tested defences, so image-derived text should stay untrusted-origin.

### Gaps
- No 2026 measurement of how often invisible-Unicode payloads occur in real mail or chat corpora was found; the only in-the-wild data are for GitHub.
- No source measured hidden-content injection through meeting transcripts, calendar invites or browser history titles.
- The two Unicode findings (lab-specific decoding tendencies) come from one paper with five models; not replicated.

## 6. Privacy: PII and secret detection beyond regular expressions, deletion that propagates, guidance on personal-data memory

### Takeaway
Small local token-classification models now outperform rule-based and regex redaction by wide margins on names and context-dependent identifiers and run on a laptop, but every source says they miss cases and are one layer; deletion is the weak spot: the one 2026 benchmark of "forget this" in agent memory found no system passing more than 1.5% of requests end to end, and European regulators' 2026 agent guidance treats memory, logs and outputs as in scope for retention limits and erasure.

### Cited Findings

#### Detection and redaction
- OpenAI Privacy Filter: open-weight (Apache 2.0) bidirectional token classifier, 1.5B total parameters with 50M active, up to 128,000 tokens of context, runs locally; eight span categories including `account_number` and `secret` ("passwords and API keys"); on PII-Masking-300k F1 96% (precision 94.04%, recall 98.04%), 97.43% on a corrected version; fine-tuning on a small domain set raised F1 from 54% to 96%. Stated limits: "not an anonymization tool, a compliance certification, or a substitute for policy review"; "can miss uncommon identifiers or ambiguous private references ... especially in short sequences". — [Introducing OpenAI Privacy Filter](https://openai.com/index/introducing-openai-privacy-filter/) (2026-04-22; vendor; opened)
- Independent benchmark REDACT (13,427 records, 51 entity types, 25 languages; five detectors on a locked 1,000-record sample: Presidio, GLiNER, OpenAI Privacy Filter, GPT-4.1, Claude Sonnet 4.6): "the rule-based detector performs poorly on the highest-stakes data, including HIGH-sensitivity categories (recall 0.07) and non-verbatim disclosure forms, while the LLM detectors remain more robust". — [arXiv:2606.19881](https://arxiv.org/abs/2606.19881) (v1 2026-06-18; authors, independent of the tool vendors; abstract)
- Multilingual encoder tagger (XLM-R-large fine-tuned on frontier-model annotations plus human corpora): redaction F1 88.2 versus 69.1 for GLiNER2 and 61.4 for Presidio on human-annotated sets in seven languages; 4.9 times faster than GLiNER2 on CPU; open-weight LLMs that fit one 96-GB GPU were less accurate and roughly 30 to 1,100 times slower. — [arXiv:2609.38630](https://arxiv.org/abs/2609.38630) (v1 2026-09-29; authors; abstract)
- Regex versus hybrid on 100 synthetic resumes (900 PII values): regex 0.20 ms median but caught 88.9% ("it cannot find names that are not known in advance"); Presidio and two hybrids (regex for structured identifiers, NER for names) caught 100% and kept 100% of business terms at 13.48–37.59 ms. — [arXiv:2611.07633](https://arxiv.org/abs/2611.07633) (v1 2026-11-05; authors, small synthetic set; abstract)
- Fully local cascade for dialogue de-identification: 0.958 macro F1 on a single laptop versus 0.767 for a same-family LLM-only baseline and 0.706 for a commercial API; ambiguity between personal names and domain terms cost only 0.03 F1. — [arXiv:2606.18372](https://arxiv.org/abs/2606.18372) (v1 2026-06-16; authors; abstract)
- Eight techniques for privacy-preserving LLM requests, 1,300 labelled samples: "no single technique dominates"; local routing plus redaction plus rephrasing reached 0.6% combined leak on PII but 31.3% on proprietary code. — [arXiv:2604.12064](https://arxiv.org/abs/2604.12064) (v1 2026-04-13; authors; abstract)
- Memory tool guidance: the model "usually refuses to write sensitive information to memory files. For stronger guarantees, add validation that strips sensitive data before your handler writes the file." — [Claude Platform docs, memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) (undated; vendor; opened)
- Classifier-side data rules: auto mode now "carries explicit rules distinguishing secrets and potentially sensitive/confidential information—and where each can be accessed and shared", and checks whether a push destination is public, private or trusted. — [Auto mode default post](https://claude.com/blog/auto-mode-default-in-claude-code) (2026-08-07; vendor; opened)

#### Deletion and unlearning in agent memory
- Bemula, the first benchmark for user-requested forgetting in agent memory (50 multi-session dialogues, 135 forget requests of six types, 1,742 test questions): "no system passes more than 1.5% of forget requests end to end, and most pass none at all". — [arXiv:2610.18052](https://arxiv.org/abs/2610.18052) (v1 2026-10-13; authors; abstract)
- "Agentic unlearning" must cover both parameters and persistent memory; the memory pathway uses "dependency closure-based unlearning that prunes isolated entities while logically invalidating shared artifacts", motivated by backflow where "memory artifacts reintroduce sensitive content". — [arXiv:2602.17692](https://arxiv.org/abs/2602.17692) (v1 2026-02-06; authors, medical QA; abstract)
- Survey of 435 works on always-on agents: "the literature concentrates more heavily on accumulating and retrieving state than on governing, recovering, or relinquishing it". — [arXiv:2606.30306](https://arxiv.org/abs/2606.30306) (v1 2026-06-29; authors; abstract)
- Selective repair of poisoned memory succeeded in 56.1% of cases in MemSecBench, another indication that removing one item's influence is unreliable. — [arXiv:2607.27080](https://arxiv.org/abs/2607.27080) (v1 2026-07-29; authors; abstract)

#### Regulatory guidance dated 2026 (all via law-firm summaries, not primary text)
- Spain's AEPD published guidance on agentic AI on 2026-02-18: it distinguishes working memory from long-term "management" memory, says both may hold personal data, treats persistent memory as a significant compliance risk, and says memory should be compartmentalised between processing activities and users, kept under strict retention periods and designed to support access, rectification and erasure. — [JD Supra summary](https://www.jdsupra.com/legalnews/aepd-publishes-guidance-on-agentic-6266860/); [Freshfields summary](https://www.freshfields.com/en/our-thinking/blogs/technology-quotient/autonomous-ai-agents-and-the-gdpr-first-detailed-spanish-regulatory-guidance-set-102mmys) (snippets only)
- France's CNIL (with CIANum) published an exploratory note on agentic AI in July/August 2026 (sources give 2026-07-20 and 2026-08-05): it distinguishes working memory from persistent memory for minimisation, calls the proliferation of memory instances the main source of opacity (users cannot tell what is retained, where and for how long), and says memory, logs and outputs fall within access and erasure requests. — [Inside Privacy](https://www.insideprivacy.com/artificial-intelligence/french-cnil-publishes-note-on-agentic-ai-and-data-protection/); [TrustArc](https://trustarc.com/products/privacy-data-governance/nymity-research/france-cnil-agent-based-ai-guidance/) (snippets only; the two dates conflict)
- OWASP's 2026 list keeps Sensitive Information Disclosure at LLM02 and adds "LLM08:2026 Hidden Context Exposure ... the unauthorized extraction, inference, or reconstruction" of hidden context. — [OWASP LLM Top 10 for 2026](https://genai.owasp.org/top-10-for-llm-applications-2026/) (opened)

### Inferences
- Pattern-based secret redaction remains the right first pass for structured secrets (the hybrid result used regex for exactly that), but personal names, addresses and context-dependent identifiers in mail, chat and transcripts need a model; a small local token classifier is now a realistic second pass on a laptop, and the vendor-reported 96% F1 has an independent data point in REDACT though not a headline number in that abstract.
- Redaction at write time is the control the memory-tool documentation recommends for stronger guarantees; applying it in the store's server-side handler keeps it independent of which client or run writes.
- "No delete tools" protects integrity against a hijacked agent but does not provide erasure. The 2026 evidence (1.5% pass rate when the model is asked to forget; dependency-closure framing) points to an owner-run, code-level deletion path that follows recorded derivation links from a source item to every claim, wiki statement and version, embedding, index entry and rendered page that depends on it, and marks shared artefacts for regeneration rather than relying on a model to rewrite them.
- The versioned wiki history and the evidence citations are themselves personal-data stores for erasure and retention purposes under the AEPD and CNIL readings; the same derivation graph that supports provenance (section 2) supports deletion.
- Tool-call traces and logs leak profile information on their own (section 3), so run logs deserve the same retention treatment as the store.

### Gaps
- I found no 2026 source that measures deletion propagation into embeddings or search indexes of an agent memory system, and no lab guidance on it; the inference above rests on one benchmark and one method paper.
- AEPD and CNIL primary documents were not opened; all regulatory statements are from secondary summaries. An EDPB/Commission guideline on GDPR and AI Act interplay is reported as expected by end of 2026 (snippet), not found.
- No 2026 benchmark of secret detection (API keys, tokens) for local models was found beyond the Privacy Filter's `secret` category claim.
- The Privacy Filter, REDACT and tagger numbers are on general PII corpora; none is evaluated on work mail or meeting transcripts.

## 7. Red-teaming and security evaluation methodology for agents in 2026

### Takeaway
2026 methodology work says static injection suites are saturated and misleading; a credible regression suite uses adaptive, defence-aware attack generation, multi-session scenarios that score planting and triggering separately, an effect-based oracle at argument level with verified payload delivery, repeated runs, and reports benign utility and false-positive cost alongside attack success. Vendor practice has moved to held-out third-party scenario sets and attempt-budget metrics (success within k attempts).

### Cited Findings

#### Benchmarks and tools released since February 2026
- Dynamic and generative successors to AgentDojo: AgentDyn (60 open-ended tasks, 560 injection cases across shopping, GitHub, daily life) — [arXiv:2602.03117](https://arxiv.org/abs/2602.03117) (v1 2026-02-03; full text); AutoDojo generates injections adaptively for a given agent and defence — [arXiv:2606.15057](https://arxiv.org/abs/2606.15057) (v1 2026-06-13; full text); MetaPI converts existing utility benchmarks into injection suites by finding injection points and optimising payloads — [arXiv:2611.10026](https://arxiv.org/abs/2611.10026) (v1 2026-11-05; abstract); INFUSE covers long-horizon coding workflows (40 tasks, 56 scenarios) — [arXiv:2610.20776](https://arxiv.org/abs/2610.20776) (v1 2026-10-14; abstract); AgentLAB covers long-horizon attacks including memory poisoning (28 environments, 644 cases) and finds single-turn defences "fail to reliably mitigate long-horizon threats" — [arXiv:2602.16901](https://arxiv.org/abs/2602.16901) (v1 2026-02-18; abstract).
- Memory-specific: MemoryDojo (155 multi-session trajectories, five memory systems, traces poison through its lifecycle) — [arXiv:2611.09721](https://arxiv.org/abs/2611.09721) (v1 2026-11-06; abstract); MemSecBench (persistence, consequence, repair) — [arXiv:2607.27080](https://arxiv.org/abs/2607.27080) (v1 2026-07-29; abstract); Trojan Hippo Bench (adaptive red-teaming with an evolutionary optimiser plus capability-aware security-utility analysis) — [arXiv:2605.01970](https://arxiv.org/abs/2605.01970) (v1 2026-05-03; full text); CarryoverBench (rule-based verifier scoring "planting and triggering as independent stages") — [arXiv:2610.28425](https://arxiv.org/abs/2610.28425) (v1 2026-10-20; full text); MPBench — [arXiv:2606.04329](https://arxiv.org/abs/2606.04329) (v1 2026-06-03; abstract); MemForm (five formation interfaces: content, evidence, scope, selection, path) — [arXiv:2610.14431](https://arxiv.org/abs/2610.14431) (v1 2026-10-10; abstract).
- Attack generators usable as regression drivers: PISmith (reinforcement-learned black-box attacker; "state-of-the-art prompt injection defenses remain vulnerable to adaptive attacks" across 13 benchmarks) — [arXiv:2603.13026](https://arxiv.org/abs/2603.13026) (v1 2026-03-13; abstract); PIArena (unified platform with a strategy-based adaptive attack; finds limited generalisation and difficulty "when an injected task aligns with the target task") — [arXiv:2604.08499](https://arxiv.org/abs/2604.08499) (v1 2026-04-09; abstract); AutoPI (taxonomy-guided, measures coverage of attack classes and not only success rate; 20–50% higher success and 25–400% higher class coverage than prior red-teamers against Claude Haiku 5.5) — [arXiv:2611.24313](https://arxiv.org/abs/2611.24313) (v1 2026-11-18; abstract); pikit (13 attacks, 16 carrier channels across text and files, 9 prevention strategies) — [arXiv:2609.36817](https://arxiv.org/abs/2609.36817) (v1 2026-09-29; abstract).
- MCP-specific: mcpvenom susceptibility matrix with a canary HTTP receipt as exfiltration oracle — [arXiv:2611.03555](https://arxiv.org/abs/2611.03555) (v1 2026-11-02; abstract); COPEX — [arXiv:2610.04378](https://arxiv.org/abs/2610.04378) (v1 2026-10-03; abstract).
- Privilege measurement: Ajar generates labelled allow/deny tests from a benchmark's benign tasks to measure the privilege a defence leaves open. — [arXiv:2609.26900](https://arxiv.org/abs/2609.26900) (v1 2026-09-22; full text)

#### Validity problems to design around
- Harness defects produce plausible wrong numbers: "silent payload non-delivery, attack success scored by tool identity rather than arguments, false-rejection rate conflated with model incapacity, and the absence of an audit trail"; re-scoring identical traces, a tool-identity scorer reported 21.7% where the argument-level rate was 1.2%, and a model reported at 62.8% registered 0% under a corrected harness. — [arXiv:2609.32691](https://arxiv.org/abs/2609.32691) (v1 2026-09-26; authors; abstract)
- Run-to-run variance: "single-run labels of thinking agents disagree with a rerun up to 35% of the time, so benchmarks need repeated runs per task". — [arXiv:2610.24048](https://arxiv.org/abs/2610.24048) (v1 2026-10-16; authors; abstract)
- Report how attacks fail and whether the user task completed: most failed attacks were ignored (76–80%) not refused, and in 21.7% of AgentDojo episodes the agent stayed safe but did not finish the user's task. — [arXiv:2610.23254](https://arxiv.org/abs/2610.23254) (v1 2026-10-16; authors; abstract)
- Separate layers: capture the raw agent-model context and classify outcomes as semantic refusal, semantic breach, interception or penetration so a result shows which layer to strengthen; "annotating untrusted content markedly improves recognition of malicious content". — [arXiv:2610.00392](https://arxiv.org/abs/2610.00392) (v1 2026-09-30; authors; abstract)
- Ablations of layered gateways mislead: in a cascade "a stage's contribution depends on what is routed to it", so switching a stage off does not measure its value. — [arXiv:2610.33198](https://arxiv.org/abs/2610.33198) (v1 2026-10-23; authors; abstract)
- Detector evaluations hide base rates and transfer: audited evaluations used 16–86% attack share and none varied it. — [arXiv:2610.41803](https://arxiv.org/abs/2610.41803) (v1 2026-10-30; authors; abstract)
- Measure cost on benign traffic with everything but the defence held fixed and several runs per condition. — [arXiv:2609.22818](https://arxiv.org/abs/2609.22818) (v1 2026-09-19; authors; abstract)
- Finite testing cannot exclude an adversary that behaves until certification: preregistered randomised AgentDojo trials estimated 1.98 additional violations per four-task continuation after "certification". — [arXiv:2610.18948](https://arxiv.org/abs/2610.18948) (v1 2026-10-13; authors; abstract)
- Static success-rate benchmarks are saturated; the swarm paper uses "random non-malicious actions as adversarial goals" to isolate instruction-hierarchy obedience from the model's knowledge of security practice. — [arXiv:2611.11861](https://arxiv.org/abs/2611.11861) (v1 2026-11-09; authors; full text)

#### Lab practice in 2026
- Attempt-budget metrics and held-out sets: success within k=1, 10, 15 attempts on a benchmark of attacks selected for transferability; adaptive attacker with 200 attempts per scenario; held-out third-party scenario sets the vendor never saw (72 scenarios x 10); find-fix-verify with a second held-out set ("caught about half of the attacks it previously missed, at a cost of missing about 2% of attacks it previously caught"). — [Anthropic Transparency Hub](https://www.anthropic.com/transparency) (opened); [Auto mode default post](https://claude.com/blog/auto-mode-default-in-claude-code) (2026-08-07; vendor; opened)
- Classifier evaluation reports false-positive rate on real traffic and false-negative rate on real incidents and synthetic exfiltration separately, per stage. — [How we built Claude Code auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode) (2026-03-25; vendor; opened)
- General evaluation hygiene from a lab: saturated single-turn sets are "useful mainly as regression checks on known failure modes"; build scenarios from observed behaviour, incident reports and red-team transcripts and treat the set as evolving; match the harness, tools and system prompt to the deployment; validate automated graders against blind human labels; preregister metrics, comparisons and thresholds; check statistical significance (a 98% versus 94% difference was not significant). — [Building strong safety evaluations](https://www.anthropic.com/research/building-strong-safety-evaluations) (2026-11-13; vendor; opened)
- Automated red-teamers trained at scale (GPT-Red) and purple-teaming loops are the labs' stated route to keeping up. — [arXiv:2607.26115](https://arxiv.org/abs/2607.26115) (v1 2026-07-28; vendor authors; abstract); [arXiv:2611.24362](https://arxiv.org/abs/2611.24362) (v1 2026-11-18; abstract)
- Canary strings in shared content containing live payloads. — [How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude) (2026-05-25; vendor; opened)

### Inferences
- A regression suite for the owner's system that follows the 2026 findings would be built from the system's own benign runs (as Ajar and MetaPI do) and would: plant payloads through each real ingestion channel (mail, chat, document, web-history title, README, commit message, transcript); cover instruction payloads, plain false facts, task-tampering values, dormant conditionals, hidden-text and invisible-Unicode carriers, and laundering through summarisation; run as two or more sessions (ingest, then compile or query) and score "written to the store", "survived validation", "reached a wiki statement" and "changed a later answer or action" as separate stages.
- The oracle should be code that inspects store rows and tool-call arguments (effect-based, argument-level), with a check that the payload was actually delivered to the model, a canary token per test, at least several repetitions per case, and the benign-task result recorded next to it.
- Because the residual risk is integrity, the suite's headline numbers should include false-claim acceptance and laundering rates, not only attack success in the injection sense; and a "leftover privilege" check (which tool calls would have been allowed that the task did not need) per run configuration.
- Static cases are worth keeping only as regression checks for known failures; new cases should come from an adaptive generator given knowledge of the wrappers and validators, and from each real incident or near miss.
- Owner approval can be tested like the vendor's 1,053-tester study: occasionally insert a clearly wrong or injected card and record whether it is confirmed.

### Gaps
- No 2026 benchmark targets a single-user claims/wiki store or the human confirmation step; all would need adapting.
- I did not verify which of the listed benchmarks ship runnable code and under what licence (several abstracts link repositories; not opened).
