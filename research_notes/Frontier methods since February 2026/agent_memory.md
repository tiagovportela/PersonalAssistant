# Agent memory and LLM-compiled knowledge bases (sources published 2026-02-01 to 2026-11-27)

Reading conventions (apply to every bullet below):

- Every arXiv citation gives the ID and the v1 submission date. All IDs are 2602.xxxxx or later. Where an ID month and the v1 date differ (held submissions), the v1 date is what counts and it is always on or after 2026-02-01.
- Provenance tags: **[independent]** = the paper evaluates systems it did not build (benchmarks, audits, controlled comparisons); **[authors' own]** = authors reporting on their own proposed system; **[vendor]** = a company or product team reporting on its own product; **[snippet]** = seen only in a web-search result snippet, the primary page could not be opened.

## 1. Memory architectures published since February 2026, and what ablations say actually matters

### Takeaway

The most consistent result of 2026's controlled studies is that keeping raw, dated source records retrievable, and getting retrieval, ranking and rendering right, matters more than LLM-built structure (extracted facts, graphs, deep hierarchies, reflection); structure gives localized gains (tight token budgets, knowledge updates, long horizons, multi-document synthesis, search cost) but no consistent accuracy advantage, and continuous LLM rewriting can make memory worse than no memory. Typed, bi-temporal, provenance-carrying records earn their place on update, "as-of", abstention, forgetting and security properties rather than on headline recall scores.

### Cited Findings

Raw records versus extraction and structure

- A naive baseline (dense retrieval plus cross-encoder reranking over raw history) ranks first among compared memory systems in 6 of 7 benchmark-model settings across LoCoMo, LongMemEval, MEME and MemoryAgentBench, by 0.13 to 5.53 points over the strongest agentic memory system. Removing the reranker costs 3.92 points (Holm p=0.0012); returning one item costs 11.73; retrieving top-120 costs 14.57; chunk sizes 128 to 1,024 do not change the total significantly. "Even complete access to transformed memory stores leaves an accuracy gap relative to raw evidence." The authors reviewed 14 prior papers and found coarse retrieval units, restricted depth or no reranking in several of their RAG baselines. **[independent] (full text)** — [arXiv 2610.30755, v1 2026-10-22](https://arxiv.org/abs/2610.30755)
- Six explicit memory systems compared with raw-history RAG on LongMemEval-S and BEAM-100K, with retriever and context budget controlled: "no consistent overall advantage over raw-history RAG", only "localized gains for some question types and under tight context budgets". Oracle retrieval separates two failure types: some systems lose answer-supporting information during memory construction, others keep it but fail to retrieve it; construction costs reach "hours per conversation". **[independent] (full text)** — [arXiv 2610.24671, v1 2026-10-17](https://arxiv.org/abs/2610.24671)
- A data-management study of 12 memory systems and 2 baselines over 11 datasets: no architecture dominates. Observation O8: "Retaining the original conversational content is more important than increasing abstraction or hierarchy" (a raw variant is best on all four metrics; a compressed variant falls from 26.0 to 10.7 substring EM on LongMemEval; summaries are weaker still; deeper trees give "only modest gains"). O7: maintenance that touches a bounded subset of memory is the most cost-efficient; systems that reorganize global state are the least (LightMem 48.3 normalized utility at 3.67 s per query; Cognee and Zep exceed 84 utility only at 116.5 s and 155.1 s). O6: flat embedding RAG falls from 37.1 to 7.4 answer F1 on LoCoMo as the evidence gap widens, while linked or consolidated memories hold up. O4: graph or relation-organized memory (Zep) leads the knowledge-update slice (44.4 substring EM). O5: changing the backbone model moves absolute quality more than it changes the ranking of memory pipelines. **[independent] (full text)** — [arXiv 2606.24775, v1 2026-06-23](https://arxiv.org/abs/2606.24775)
- Program evolution over whole memory systems (MAPE) converges on two recurring patterns: "retaining raw conversations as retrievable evidence preserves details omitted from extracted memories", and composing retrieved evidence by query intent before answering (transplanting that composition module into five existing systems improved all five). Up to +12% absolute accuracy at 35% of serving cost on LoCoMo; when cost is part of the objective, search moves compute from LLM-based memory construction to selective query-time processing. **[authors' own] (full text)** — [arXiv 2611.17068, v1 2026-11-12](https://arxiv.org/abs/2611.17068)
- BRIDGE, a deliberately minimal memory (one observation note per block chained to the 10 previous notes, hybrid BM25 plus cosine retrieval fused by RRF, chronological rendering with 3 raw-source slots; one LLM call per ingested block and one per query; about 5 to 7K reader tokens), reaches parity within bootstrap CI with prior reported SOTA on LongMemEval-S and BEAM and beats the best memory baseline on EverMemBench by 5.7 to 6.3 points, with "no supersession layer, reflection step, graph synthesis, or working-memory cache". Leave-one-out ablation: each primitive moves pooled accuracy by only 0 to 6 points but moves the category it serves by 5 to 30 points; removing raw-source slots costs 30.2 points on LongMemEval-S single-session-assistant questions (95% CI [-42.9, -19.6]); EverMemBench memory-update swings by about 38 points between BM25-only and cosine-only retrieval. On five behavioural probes (rule application, pattern induction, multi-turn) no design wins everywhere: atomic-fact extractors win rule application, block-summary memory wins pattern induction. **[authors' own baseline, compared against published systems] (full text)** — [arXiv 2611.22179, v1 2026-11-17](https://arxiv.org/abs/2611.22179)
- ReFind: no semantic structure at all; the archive is indexed lexically per turn and an agent runs an iterative keyword-search loop with four controls (session-aware rank fusion, local context expansion, temporal narrowing, skipping already-inspected sessions). Mean accuracy 58.2 on about 2,800 MemoryAgentBench questions versus 53.2 for HippoRAG 2 (GPT-4o-mini for all); 93.2 +/- 3.3 and 89.3 +/- 6.0 on LongMemEval-S/M with GPT-5-mini. **[authors' own]** — [arXiv 2608.12888, v1 2026-08-13](https://arxiv.org/abs/2608.12888)
- SmartSearch: fully deterministic retrieval over raw history (NER-weighted substring matching, rule-based entity expansion) plus one learned stage (CrossEncoder plus ColBERT rank fusion, about 650 ms on CPU): 93.5% LoCoMo and 88.4% LongMemEval-S with 8.5x fewer tokens than full context. Oracle analysis: retrieval recall is 98.6%, but without ranking only 22.5% of gold evidence survives truncation to the token budget. **[authors' own]** — [arXiv 2603.15599, v1 2026-03-16](https://arxiv.org/abs/2603.15599)
- Pre-registered test: at a tight budget on LoCoMo, raw turns picked by one call to a typed decision model are non-inferior to an LLM-extraction memory (one-sided 95% bound -3.0 against a -5 margin) and cost 3,061 times less to write. Reranking adds 17.4 points (LoCoMo) and 9.1 (LongMemEval) when 3 of 30 candidates are kept, but only 1.5 and 1.1 at generous budgets, where extraction systems are more accurate; reranking lowers correct abstention. **[authors' own, pre-registered]** — [arXiv 2609.34227, v1 2026-09-28](https://arxiv.org/abs/2609.34227)
- Independent analysis of MemPalace (verbatim storage, zero-LLM write path, about 170-token wake-up): its 96.6% Recall@5 on LongMemEval is "attributable primarily to its verbatim storage philosophy combined with ChromaDB's default embedding model", and the palace hierarchy "operates as standard vector database metadata filtering". The same paper relays that Mem0's April 2026 algorithm raised its LongMemEval score from about 49% to 93.4% (a vendor figure). **[independent]** — [arXiv 2604.21284, v1 2026-04-23](https://arxiv.org/abs/2604.21284)
- True Memory: events preserved verbatim in "a single SQLite file on commodity CPU with no external database, vector index, graph store, or GPU", with a multi-stage retrieval pipeline: 93.0% LoCoMo (reported against Mem0 61.4%, Supermemory 65.4%, Zep about 71%, EverMemOS 94.5% with a matched gpt-4.1-mini answerer), 87.8% LongMemEval, 76.6% BEAM-1M; a 56-configuration ablation shows a 1.3-point spread within the top configuration family. **[vendor]** — [arXiv 2605.04897, v1 2026-05-06](https://arxiv.org/abs/2605.04897)
- EdgeMem: memory construction and retrieval with no generative-LLM calls (original turns organized by content, temporal and episodic anchors): highest strict-judge score among seven reproduced systems on LoCoMo (61.01 versus 58.70). **[authors' own]** — [arXiv 2609.05553, v1 2026-09-03](https://arxiv.org/abs/2609.05553)
- Controlled test of hierarchy depth versus context width on EverMemBench: widening the context from 1K to 4K tokens adds 10.11 to 17.98 accuracy points; deeper structure (D1 to D4) gives "no monotonic gain"; gains plateau beyond 8 to 16K tokens. **[independent]** — [arXiv 2610.08300, v1 2026-10-06](https://arxiv.org/abs/2610.08300)
- The form in which evidence reaches the reader matters as much as what is retrieved: holding the conversation fixed and varying only the rendered artifact, the best-worst spread across deployed-style templates is 24.6 to 48.8 points per model; natural-language memory entries beat raw conversation on 7 of 9 models; three models score 0% on formal ledger-style packets but 45.4 to 53.4% on the same facts as natural-language entries. **[independent]** — [arXiv 2608.23568, v1 2026-06-05](https://arxiv.org/abs/2608.23568)

Typed, temporal and bi-temporal memory

- Engram (bi-temporal): the write path appends lossless episodes with no LLM; an asynchronous path extracts subject-predicate-object facts and resolves contradictions without an LLM call per fact, "invalidating, never deleting"; the read path fuses dense, lexical, graph and recency signals and applies an "as-of" filter. 83.6% versus 73.2% for full context on LongMemEval-S (+10.4, McNemar p < 10^-6) from 9.6k instead of 79k tokens; knowledge-update 87.5%, temporal 81.1%. "Facts alone lose recall, while facts plus retrieved chunks recover detail." **[authors' own] (full text)** — [arXiv 2606.09900, v1 2026-06-05](https://arxiv.org/abs/2606.09900)
- APEX-MEM: property graph with a domain-agnostic ontology, append-only storage, and a retrieval agent that resolves conflicting or evolving information at query time: 88.88% LoCoMo, 86.2% LongMemEval. **[authors' own]** — [arXiv 2604.14362, v1 2026-04-15](https://arxiv.org/abs/2604.14362)
- A Neo4j bitemporal store (valid time and transaction time on versioned content nodes): on 60 sampled LongMemEval questions, 46.7% R@10 overall and 80% on knowledge-update; the time-travel path lowered recall on temporal-reasoning questions (50% to 37.5%) because of post-filter dilution. **[authors' own, small sample]** — [arXiv 2607.26520, v1 2026-07-29](https://arxiv.org/abs/2607.26520)
- Longitudinal benchmark of five memory architectures: a budgeted curated-map memory leads at three weeks (94.2%) but its recall of early content falls from 96.3% to 72.2% by nine weeks, while a provenance-typed graph rises to 90.4% and a layered hybrid to 93.2% ("tenure crossover"). A full-rendered-history baseline ties or beats the best memory system at the short horizon but has no judge-independent advantage at nine weeks, at about twice the read cost. Weakly written facts fail 24% of the time versus 2%. The provenance-typed graph (third-party claims stored as claims, with the claimant as source) blocked all 14 planted injection probes; "the operative boundary is provenance surviving representation, not graph topology per se". The accuracy winner almost never abstains: 93.9% of its errors are confidently asserted. **[independent benchmark; the authors also release one of the tested systems] (full text)** — [arXiv 2607.21962, v1 2026-07-24](https://arxiv.org/abs/2607.21962)
- Explicit state beats long context beyond a reader-dependent horizon: open models reading a full access log fall from 72-86% (8 or 16 events) to 48-55% (256 events); a filter in which a model parses each line and an explicit rule applies the update answers 80-89% at 256 events and beats relevance retrieval, model-kept ledgers and the Mem0 library. **[authors' own]** — [arXiv 2611.02361, v1 2026-11-02](https://arxiv.org/abs/2611.02361)
- TOKI formalizes the four contradiction heuristics used in production (last-writer-wins, evidence-weighted merge, await-confirmation, per-rule policy) as bitemporal operators that keep the losing fact in an audit row. In its audit of eight systems, "every baseline that keeps a language-model judge on the write path admits at least one of three write-time anomalies (replay inconsistency, belief-drift skew, audit erasure)". The measured accuracy effect is small (the audit row moves LoCoMo by 0.86; ablating the typed layer removes 0.49). **[authors' own]** — [arXiv 2606.06240, v1 2026-06-04](https://arxiv.org/abs/2606.06240)
- Schema-grounded memory (xmemory): interpretation moves to a validated write path so that reads are "constrained queries over verified records"; 97.10% F1 on the authors' end-to-end benchmark versus 80.16-87.24% for third-party baselines; extraction reaches 90.42% object-level but only 62.67% output accuracy. **[vendor, own benchmark]** — [arXiv 2604.27906, v1 2026-04-30](https://arxiv.org/abs/2604.27906)
- Episodic memory (REMem): a hybrid graph linking time-aware gists and facts with an agentic retriever improves on Mem0 and HippoRAG 2 by 3.4 and 13.4 absolute points on episodic recollection and reasoning, with more robust refusal on unanswerable questions. **[authors' own]** — [arXiv 2602.13530, v1 2026-02-13](https://arxiv.org/abs/2602.13530)
- MIRIX-2.0: six typed memory agents "keep complete records as the system of record", a provenance hypergraph indexes episodic and semantic records with frames "that cite their rows", and AutoDream "merges duplicate anchors outside the write path without rewriting any record": 91.4% LoCoMo, 72.6% LongMemEval-S. **[authors' own]** — [arXiv 2611.12068, v1 2026-11-09](https://arxiv.org/abs/2611.12068)
- Bayesian belief memory gives "little benefit over naive last-write-wins" on LoCoMo "because existing conversational memory benchmarks rarely contain contradictory or differently reliable evidence"; it helps only when observations differ in trustworthiness. **[authors' own]** — [arXiv 2606.22030, v1 2026-06-20](https://arxiv.org/abs/2606.22030)

Memory as files and agent-organized stores

- First systematic study of filesystem memory (markdown tree managed with generic file tools), varying shape, scale, tool harness and model strength: organization "roughly halve[s] retrieval cost where material is large" (PersonaMem 32k: 1.4 cents per query for reorganized stores versus 4.0 for a verbatim dump; 128k: 1.6 versus 3.9), but "no agent we measure converts organization itself into better answers". The cheapest structure, verbatim session files grouped into folders, is the most consistent leader (LoCoMo 86.1, REALTALK 77.6, PersonaMem-128k 76.2); the agent-curated store is the weakest of all on PersonaMem 32k (37.5 versus 78.1 for the verbatim dump and 71.9 for chunk retrieval). Adherence to the taxonomy "erodes as most stores grow, and only the strongest management agent holds it"; "changing the tool set alone reshapes the store as strongly as swapping the model". Caveat stated by the authors: columns rest on 32 to 158 questions. **[independent] (full text)** — [arXiv 2607.26637, v1 2026-07-29](https://arxiv.org/abs/2607.26637)
- SoMem: the agent organizes linked documents itself; "every summary it produces stays linked to the original interactions as evidence"; the runtime validates updates and derives temporal, relational and recent-memory views. +2.66, +3.10 and +2.00 points over the strongest baseline on LoCoMo, BEAM-100K and LongMemEval-S. **[authors' own]** — [arXiv 2611.11929, v1 2026-11-09](https://arxiv.org/abs/2611.11929)
- Infini Memory: topic documents as the unit of memory, a staging buffer with periodic consolidation, and iterative tool-based reading: 64.7% overall on MemoryAgentBench. **[authors' own]** — [arXiv 2606.10677, v1 2026-06-09](https://arxiv.org/abs/2606.10677)
- ByteRover: markdown files in a Domain / Topic / Subtopic / Entry tree, each entry with relations, provenance, importance score, maturity tier and recency decay; 5-tier retrieval resolves most queries in under 100 ms without LLM calls; no vector or graph database. **[vendor]** — [arXiv 2604.01599, v1 2026-04-02](https://arxiv.org/abs/2604.01599)
- LongMemEval-V2: storing agent trajectories as files and letting a coding agent gather evidence (AgentRunbook-C) scores 72.5% versus 48.5% for the strongest RAG baseline and 69.3% for an off-the-shelf coding agent, but coding-agent methods "have high latency costs" (about 182 s per query for a coding-agent method, about 6.9 times slower than the RAG variant). **[authors' own systems on their own benchmark] (full text)** — [arXiv 2605.12493, v1 2026-05-12](https://arxiv.org/abs/2605.12493)
- A negative result on experience memory: across five stores (none, markdown file, vector database, graph, git) and pre-registered repeats, memory of past problems did not improve accuracy on new problems; it helps only when the new problem is nearly identical to a stored one (cosine similarity above about 0.8). **[authors' own]** — [arXiv 2606.14470, v1 2026-06-12](https://arxiv.org/abs/2606.14470)

Consolidation, sleep-time and "dreaming"

- LLM-consolidated memory degrades with repeated updates: utility "first rises, then degrades, and can fall below the no-memory baseline"; consolidating from ground-truth solutions, GPT-5.4 fails 54% of ARC-AGI problems it had solved without memory; the same trajectories give different memories under different update schedules; an episodic-only control (raw trajectories) "remains competitive"; agents given Retain / Delete / Consolidate actions keep raw episodes by default and double the accuracy of forced consolidation. Recommendation: "Abstraction should be selective, delayed, and grounded in recoverable trajectories." **[independent] (full text)** — [arXiv 2605.12978, v1 2026-05-13](https://arxiv.org/abs/2605.12978)
- When to consolidate depends on the token budget: on LongMemEval consolidation improves absolute accuracy by up to 48% under tight budgets while retention of raw records is better under loose budgets (LoCoMo shows the same crossover at a smaller budget); cross-note abstraction and merging beat local rewriting. **[authors' own]** — [arXiv 2607.17545, v1 2026-07-20](https://arxiv.org/abs/2607.17545)
- Mnemon: conversations are kept as raw dated records; a background pass "consolidates each record once into topic timelines, value histories and standing instructions linked to the records"; small fast yes/no judgments select evidence. 91.7% LoCoMo and 83.8% LongMemEval-S with gpt-4.1-mini from under 4k tokens; 92.2% and 94.4% with a reasoning model; cost per question grows by a factor of 1.11 from 100K to 10M tokens on BEAM. **[authors' own]** — [arXiv 2609.36059, v1 2026-09-28](https://arxiv.org/abs/2609.36059)
- MemDream: periodic offline cycles in which agents probe, diagnose and repair the memory graph before real queries expose failures, with reversible soft decay: +4.5 F1 on LoCoMo and +9.1 overall on MemoryAgentBench over the strongest reactive baselines. **[authors' own]** — [arXiv 2609.34545, v1 2026-09-28](https://arxiv.org/abs/2609.34545)
- RSPM: at intervals the agent clusters recent failures, distills each cluster into a rule, deletes the raw episodes, lets rules decay unless reinforced: +9.1, +11.9 and +7.6 points on three settings, with about 93% fewer retry loops and about 30% fewer stored entries. **[authors' own]** (note: it deletes raw episodes, the opposite of what 2605.12978 recommends) — [arXiv 2610.25561, v1 2026-10-18](https://arxiv.org/abs/2610.25561)
- A nightly-rewrite memory (Claude Opus 5.5 rewriting a size-limited text memory from each day's transcript, ten simulated days built from LongMemEval): replacing details in 40% of turns lowered recall from 76% to 60%; "Replaced details were stored as fact even when another turn held the correct value"; random-text corruption had no consistent effect because the model recognized it and left it out. **[independent]** — [arXiv 2611.21648, v1 2026-10-14](https://arxiv.org/abs/2611.21648)
- MEMOIR: gates each merge on whether answer-relevant evidence is preserved, and revises retrieval priority after use. The retrieval stack improves evidence recall@5 by 11.92 points over bare cosine; the judge-gated merge itself barely matters (recall 58.82% to 59.08%, active store reduced by 1.42%). **[authors' own]** — [arXiv 2611.07631, v1 2026-11-05](https://arxiv.org/abs/2611.07631)
- Deployment report (lessons mined from trajectories, consolidated into guidelines; shipped in IBM products): "the right amount of memory is a property of the model, not the memory". A strong model keeps improving with all 191 guidelines (+9.5 points task completion); a weaker one goes from 39.9% to 51.2% with all 199 guidelines but 55.4% with about 29 selected ones. Listed failures include "a high-support guideline that backfired" and "provenance silently dropped during consolidation". **[vendor deployment report]** — [arXiv 2611.26361, v1 2026-11-19](https://arxiv.org/abs/2611.26361)
- Write cost of LLM-maintained views: "ingesting one conversation takes 15-53 minutes with leading memory systems". MemForest treats every view as derived from durable facts and recomputes it only from its children in a time-ordered tree (4.7x faster build than EverMemOS on LongMemEval-S, 84.1% LoCoMo, 81.8% LongMemEval-S with Qwen3-30B). **[authors' own]** — [arXiv 2605.23986, v1 2026-05-16](https://arxiv.org/abs/2605.23986)
- Position paper mapping phases of biological sleep to memory operations; it offers a prediction (selectionist consolidation will beat instructionist alternatives as stores grow), not results. **[opinion]** — [arXiv 2611.02216, v1 2026-11-01](https://arxiv.org/abs/2611.02216)

Forgetting and decay

- What budget eviction destroys: on LongMemEval-S at an 80k-token budget, the irreversible share of errors is 0.67-0.73 for FIFO, random and redundancy-aware eviction and 0.60 for LLM-importance eviction; at 8k tokens it is 1.00 for all four policies. **[independent]** — [arXiv 2609.08279, v1 2026-09-08](https://arxiv.org/abs/2609.08279)
- Where the LLM sits in the mutation path (supersede, release, purge) across 13 configurations: deterministic primitives suffice for lexical and temporal cases but fail canonicalization (5% on identifier obfuscation, 0% on cross-lingual cases); an LLM at write time recovers canonicalization (100%) but not intent-aware deletion (0%); an LLM hook at mutation time reaches 91.7-93.2% overall at $0.17 per 385-case run and 2.3 s per case, with the recall path unchanged. "Production failures are predominantly forgetting failures rather than recall failures, yet existing benchmarks measure only recall." **[authors' own benchmark, ForgetEval]** — [arXiv 2606.15903, v1 2026-06-14](https://arxiv.org/abs/2606.15903)
- Explicit forget requests: across six memory systems and three backbones, "no system passes more than 1.5% of forget requests end to end"; systems either leave the information extractable or delete far more than requested. **[independent]** — [arXiv 2610.18052, v1 2026-10-13](https://arxiv.org/abs/2610.18052)
- Excluding forgotten or updated items outright rather than down-weighting them: 4.04% versus 19.66% balanced construct error on the Memora "Remembering" task (Qwen3-8B), driven by leakage of forgotten values. **[authors' own]** — [arXiv 2609.37474, v1 2026-09-26](https://arxiv.org/abs/2609.37474)
- Decay as reduced accessibility rather than deletion (Oblivion): outperforms baselines while cutting token cost by up to 73% at 120K interaction spans. **[authors' own]** — [arXiv 2604.00131, v1 2026-03-31](https://arxiv.org/abs/2604.00131)
- Memory Worth: two counters per memory (co-occurrence with successful versus failed outcomes) reach Spearman 0.89 +/- 0.02 with true utility after 10,000 episodes in a synthetic environment; the authors stress it is associational, not causal. **[authors' own, synthetic]** — [arXiv 2604.12007, v1 2026-04-13](https://arxiv.org/abs/2604.12007)

Procedural memory

- Skills as procedural memory on 382 enterprise tasks: one refinement round improves aggregate performance by 3.7-6.7 points; skills evolved from multi-model traces reach 73.1% cross-model accuracy; some skills specialize and lose effectiveness under transfer. **[authors' own benchmark, AFTER]** — [arXiv 2606.23127, v1 2026-06-22](https://arxiv.org/abs/2606.23127)
- On real repository coding tasks, injecting verified prior experience directly raises task resolution by 1.1 to 4.5 points on four of five solvers, yet when four existing memory systems must construct and retrieve that experience themselves, "eleven of twelve solver and system pairings fail to exceed the matched memory-off baseline". **[independent]** — [arXiv 2609.23570, v1 2026-09-20](https://arxiv.org/abs/2609.23570)

Cost

- Fact-based memory (Mem0 framework) versus long-context inference with GPT-5-mini: long context has higher recall on LongMemEval and LoCoMo, the memory system is competitive on PersonaMemv2; at 100k tokens of context the memory system becomes cheaper after about ten turns, even with prompt caching. **[independent]** — [arXiv 2603.04814, v1 2026-03-05](https://arxiv.org/abs/2603.04814)

### Inferences

- For a store like the Personal Work Intelligence layer, the raw events, commits and session rows should stay the system of record and stay searchable; derived layers (claims, wiki pages) are views over them. This matches the strongest independent results (2610.30755, 2610.24671, 2606.24775, 2605.12978) and the patterns that program search rediscovers (2611.17068).
- SQLite FTS5 keyword search is not the weak point the vector-database literature would suggest: lexical or hybrid retrieval with good controls reaches top-tier results (ReFind, SmartSearch, BRIDGE, True Memory on a single SQLite file). The best-supported additions, in order of evidence, are (1) a ranking stage over a broader candidate set (reranker removal costs 3.9 points in 2610.30755; ranking adds 9 to 17 points at tight budgets in 2609.34227), (2) agent-facing search controls such as temporal narrowing, per-session/per-project fusion and local context expansion (2608.12888), (3) chronological rendering with dates and source ids (2611.22179), and (4) query-intent-specific composition of the evidence (2611.17068). A small CPU cross-encoder is feasible (about 650 ms on CPU in 2603.15599) but would break the standard-library-only constraint, so the controls in (2) and (3) are the cheaper first step.
- Typed claims with validity state, provenance and supersession chains are justified by update, "as-of", abstention, forgetting and injection-resistance results (2607.21962, 2606.09900, 2611.02361), not by aggregate accuracy. A "label computed at read time" design sits close to the "preserve at write, resolve at read" line of work (section 3).
- Consolidation should be gated, delayed, bounded in scope and reversible rather than run after every interaction (2605.12978, 2606.24775 O7, 2611.26361), and every consolidated item should keep links to the records it came from (2611.11929, 2609.36059, 2611.12068).
- Budget- or age-based deletion of unconfirmed data is the riskiest lifecycle step: eviction losses are mostly irreversible (2609.08279) and rankings of architectures invert once early content is evicted (2607.21962). A 90-day retention rule for unconfirmed data therefore needs a "promote or summarize before expiry" check rather than silent deletion.
- Bilingual stores are exposed with keyword-only matching: deterministic primitives scored 0% on cross-lingual canonicalization in ForgetEval (2606.15903), and a vendor test reports BM25 at 19.0% mean recall@5 over 70 cross-language cells (2608.23920, section 2). Canonicalizing entities when the LLM writes a claim (the "inscribe-time LLM recovers canonicalization" result) is the mitigation that fits a no-embedding system; this is an inference, no source tested Portuguese-English specifically.

### Gaps

- No 2026 source evaluates memory built from heterogeneous personal telemetry (Git metadata, browser history, app usage). Benchmarks are conversational or agent trajectories; two candidates I did not open in full are Setoka (arXiv 2607.27056, heterogeneous user data) and FileGram (arXiv 2604.04901, file-system behavioural traces).
- Most architecture numbers are the authors' own, on LoCoMo or LongMemEval, with different readers and judges. I found no neutral leaderboard that fixes reader, judge and prompt.
- For the majority of papers I read only the abstract; ablation details beyond the abstract are unverified for those.
- No source on Portuguese-English memory specifically, and none on memory quality with a human confirmation step in the loop.
- I did not check openreview.net or aclanthology.org for peer-review status of any of these preprints.

## 2. Benchmarks since February 2026: what they test, top results, and criticism of validity

### Takeaway

2026 benchmarks move away from conversational recall (LoCoMo and LongMemEval are near-saturated and shown to swing by 7 to 9 points with the judge or answer prompt alone) toward agent trajectories, state tracking, staleness, forgetting and task completion; on those, existing memory systems frequently fail to beat BM25, raw-history RAG or no memory at all. Headline scores from different papers cannot be ranked against each other.

### Cited Findings

New or updated benchmarks and what they test

- LongMemEval-V2: 451 manually curated questions over web-agent trajectories (up to 500 trajectories and 115M tokens) covering static state recall, dynamic state tracking, workflow knowledge, environment gotchas and premise awareness; memory systems return compact evidence that a fixed reader answers from; best result 72.5% (authors' file-plus-coding-agent method). **[authors' own top result] (full text)** — [arXiv 2605.12493, v1 2026-05-12](https://arxiv.org/abs/2605.12493)
- AMA-Bench: memory over real and synthetic agent-environment trajectories (states, actions, observations, tool outputs) instead of dialogue; existing systems "fail to capture causal and objective information and rely heavily on lossy similarity-based retrieval"; best 57.22% (authors' AMA-Agent, +11.16 over the strongest baseline). **[authors' own top result]** — [arXiv 2602.22769, v1 2026-02-26](https://arxiv.org/abs/2602.22769)
- MemoryArena: human-crafted multi-session tasks with interdependent subtasks (web navigation, preference-constrained planning, progressive search, formal reasoning); "agents with near-saturated performance on existing long-context memory benchmarks like LoCoMo perform poorly". **[independent]** — [arXiv 2602.16313, v1 2026-02-18](https://arxiv.org/abs/2602.16313)
- EverMemBench: multi-party, multi-group conversations of over one million tokens, 2,400 QA pairs on fine-grained recall, memory awareness and profile understanding; multi-hop reasoning collapses under multi-party attribution "even with oracle evidence (26% accuracy)" and "temporal reasoning fails without explicit version semantics beyond timestamps". **[independent]** — [arXiv 2602.01313, v1 2026-02-01](https://arxiv.org/abs/2602.01313)
- Memora: weeks-to-months conversations with three tasks (remembering, reasoning, recommending) and the FAMA metric, which penalizes use of obsolete memory; four LLMs and six memory agents show "frequent reuse of invalid memories"; "memory agents offer marginal improvements". **[independent]** — [arXiv 2604.20006, v1 2026-04-21](https://arxiv.org/abs/2604.20006)
- STALE: 400 expert-validated implicit-conflict scenarios (1,200 queries, contexts up to 150K tokens) probing state resolution, premise resistance and implicit policy adaptation. Best model (Gemini-3.1-pro with the full history in context) 55.2% overall; Qwen3.5-27B 31.3%; "most memory frameworks fall below 10%". **[independent] (full text)** — [arXiv 2605.06527, v1 2026-05-07](https://arxiv.org/abs/2605.06527)
- StaleBench: 892 real updating facts with currency labels from Wikidata validity years; shows that "retrieval metrics can rank memory policies backwards" and adds Contamination@5. **[independent] (full text)** — [arXiv 2611.19752, v1 2026-11-15](https://arxiv.org/abs/2611.19752)
- MemDerive: derived state that no single record states (10 scenarios, 4,692 events, 1,503 queries, gold answers and derivation DAGs from Datalog). "On derived state, every memory system falls behind simple BM25 retrieval, although the same answer model reaches 96.01% when given the supporting events"; most failures are "ungathered" state that the system holds but does not retrieve. **[independent]** — [arXiv 2610.25373, v1 2026-10-18](https://arxiv.org/abs/2610.25373)
- FEB-30: 30 fact-evolution trajectories with deterministic ground truth, inspecting the memory store after each ingestion step. Intrinsic (store contents) and extrinsic (QA) scores diverge by 16 percentage points on average, 44% of trajectories diverge meaningfully, and the tested system classifies memory operations (create, update, reinforce, supersede) correctly only 20% of the time, "a failure entirely invisible to extrinsic evaluation". **[independent, one system tested] (full text)** — [arXiv 2610.22209, v1 2026-10-15](https://arxiv.org/abs/2610.22209)
- DolphinBench: memory evaluated through task completion for three knowledge-work personas (about 500k tokens of user messages each, 200 tasks each, every task verified to succeed with the history and fail without it), with mandatory reporting of cost and latency. **[independent]** — [arXiv 2609.24971, v1 2026-09-21](https://arxiv.org/abs/2609.24971)
- "Ground truth first" instrument: facts with validity intervals, volatility classes and source channels are sampled before any text exists, then rendered into chat and email; about 380 questions of 15 types, including as-of-date questions, sent/received trust distinctions and injection probes. **[independent] (full text)** — [arXiv 2607.21962, v1 2026-07-24](https://arxiv.org/abs/2607.21962)
- Others, by ability: LoCoMo-Plus (latent constraints where cue and trigger are semantically disconnected) — [arXiv 2602.10715, v1 2026-02-11](https://arxiv.org/abs/2602.10715); AMemGym (interactive, on-policy evaluation with simulated users) — [arXiv 2603.01966, v1 2026-03-02](https://arxiv.org/abs/2603.01966); StreamMemBench (from streaming observation to later assistance; eight systems "often fail to use observed evidence or turn feedback into reliable follow-up behavior") — [arXiv 2606.14571, v1 2026-06-12](https://arxiv.org/abs/2606.14571); DyadMem (61,210 QA instances; "Gold-Memory QA is consistently strong, yet Full-Pipeline QA drops sharply") — [arXiv 2610.03020, v1 2026-10-02](https://arxiv.org/abs/2610.03020); MemArena (on-device personal memory with open-weight readers; switching the memory backend gains +22.1/+21.2 points while scaling the reader from Qwen3-8B to 32B gains at most +3.5/+4.4) — [arXiv 2608.02613, v1 2026-05-20](https://arxiv.org/abs/2608.02613); Bemula (memory unlearning) — [arXiv 2610.18052, v1 2026-10-13](https://arxiv.org/abs/2610.18052); ForgetEval — [arXiv 2606.15903, v1 2026-06-14](https://arxiv.org/abs/2606.15903); VibeMemBench (coding) — [arXiv 2609.23570, v1 2026-09-20](https://arxiv.org/abs/2609.23570). **[all independent benchmarks; abstracts only]**
- BEAM as 2026 papers describe it: BEAM-100K "contains 20 conversations, each with 20 questions (400 in total), spanning a broader set of conversational memory abilities, including knowledge updating, multi-session reasoning, instruction and preference following, summarization, temporal reasoning, and abstention" — [arXiv 2610.24671, v1 2026-10-17](https://arxiv.org/abs/2610.24671); results are reported as a mean over ten abilities — [arXiv 2611.22179, v1 2026-11-17](https://arxiv.org/abs/2611.22179); the scale tiers run from 100K to 10M tokens — [arXiv 2609.36059, v1 2026-09-28](https://arxiv.org/abs/2609.36059); the 1M tier has 700 questions — [arXiv 2605.04897, v1 2026-05-06](https://arxiv.org/abs/2605.04897).

Criticism of benchmark validity

- LoCoMo scores are moved by evaluation choices as much as by memory quality: "Changing only the judge moves a score by up to 7.2 points and changing only the answer prompt by up to 9.3"; with gpt-4.1-mini answers a memory system and the whole-conversation baseline score the same (83.2 versus 83.1). **[vendor evaluating its own system as a black box, all answers released]** — [arXiv 2611.19199, v1 2026-11-14](https://arxiv.org/abs/2611.19199)
- LoCoMo label quality, as cited by a 2026 paper: an independent non-peer-reviewed audit (Penfield Labs, 2026) found 6.4% of the answer key (99 of 1,540) has score-corrupting errors and that an LLM judge accepted 62.81% of deliberately wrong answers. **[independent audit, reported second-hand] (full text of the citing paper)** — [arXiv 2607.21962, v1 2026-07-24](https://arxiv.org/abs/2607.21962)
- "An empty-gold scoring bug in the LOCOMO reference implementation ... renders 23% of its corpus unscorable by construction"; by the authors' property analysis, the median existing memory benchmark covers 1 of 7 "continuity" properties. **[authors' claim, promoting their own standard]** — [arXiv 2604.10981, v1 2026-04-13](https://arxiv.org/abs/2604.10981)
- Context saturation: LoCoMo (about 20k tokens) "remains comfortably in-window for modern models"; only datasets far beyond the window (LongMemEval-M at over 1M tokens) structurally require external memory. The survey also flags misaligned metrics (F1 versus semantic correctness), judge prompt sensitivity, backbone dependence and unreported latency and throughput costs, and proposes always reporting the gap to a full-context baseline. **[independent] (full text)** — [arXiv 2602.19320, v1 2026-02-22](https://arxiv.org/abs/2602.19320)
- Reader and harness effects: holding engine, corpus and judge fixed, changing only the reader moves LongMemEval-S by 2.0 points and changing only the re-ask budget moves BEAM-1M by 8.9, which "exceeds most gaps" between published systems. **[vendor]** — [arXiv 2608.23920, v1 2026-08-24](https://arxiv.org/abs/2608.23920)
- Grading effects: the same answers score 90.91% under source-aware grading and 78.25% under reference-only grading on LoCoMo; a same-seed replay of unchanged requests changed 1.5-2.3% of labels. **[authors' own]** — [arXiv 2610.05343, v1 2026-10-04](https://arxiv.org/abs/2610.05343). A separate paper measures a 27.5-point discrepancy between strict token-F1 and LLM-judge scoring on identical outputs. — [arXiv 2606.22030, v1 2026-06-20](https://arxiv.org/abs/2606.22030)
- MemoryAgentBench's conflict-resolution split: the benchmark's own rule (newest statement wins), run as a frozen resolver, answers 80.25% of the questions; 67 items have a gold answer that the last-write graph cannot reach but the overwritten statements would; long-context models score 82.6-84.7% on rule-solvable items and 10.4-11.9% on those 67. **[independent]** — [arXiv 2610.09193, v1 2026-10-06](https://arxiv.org/abs/2610.09193)
- "This parity does not mean Bridge is a better memory system: it means these benchmarks cannot tell memory designs apart." BEAM's original event-ordering metric is unreliable ("even gold answers score only ~0.7"). **(full text)** — [arXiv 2611.22179, v1 2026-11-17](https://arxiv.org/abs/2611.22179)
- Fixed-snapshot accuracy hides scale effects: with task evidence held fixed and irrelevant sessions added, one graph memory loses 16-20 points of budget-compliant reliability on LongMemEval, and another system's failures depend on the agent model. **[independent]** — [arXiv 2605.07313, v1 2026-05-08](https://arxiv.org/abs/2605.07313)
- End-to-end QA cannot say where a failure comes from: an operation-level diagnostic over seven systems attributes 22.1% of default LoCoMo failures to retrieval, 7.7% to encoding and 6.5% to generation. **[independent]** — [arXiv 2609.22231, v1 2026-09-03](https://arxiv.org/abs/2609.22231)
- Harness pitfalls documented by one team: truncation, home-grown judges and full-history leaks "silently distort memory benchmarks"; "one system appears at wildly different scores across sources". **[authors' own] (full text)** — [arXiv 2606.09900, v1 2026-06-05](https://arxiv.org/abs/2606.09900)
- Proactive recall does not scale with a similarity threshold: a threshold tuned to 5% false alarms with 8 stored memories produces 84-100% false alarms at 2,048 memories on LongMemEval replays. **[independent]** — [arXiv 2610.34507, v1 2026-10-25](https://arxiv.org/abs/2610.34507)

### Inferences

- LongMemEval's ability list (information extraction, multi-session reasoning, knowledge updates, temporal reasoning, abstention) is still the common vocabulary, but 2026 work adds abilities that map directly onto a personal work store: staleness and implicit conflict (STALE, StaleBench, Memora/FAMA), derived state (MemDerive), premise awareness (LongMemEval-V2), forgetting on request (Bemula, ForgetEval), and task completion with cost (DolphinBench).
- For evaluating a private system, the most transferable method is "ground truth first" (2607.21962) plus intrinsic inspection (2610.22209): seed synthetic facts with validity intervals, render them as fake commits, sessions and browser events, ingest, then check both the store (were claims created, superseded, labelled correctly?) and the answers. A QA-only evaluation would miss the 16-point intrinsic/extrinsic divergence.
- Any internal comparison should fix reader model, judge and answer prompt, include a raw FTS-only baseline and a full-context baseline, and report token cost, because each of those choices alone moves scores by 2 to 9 points in the 2026 audits.
- Public scores above about 90% on LoCoMo or LongMemEval-S carry little design information: label error (6.4% reported), judge leniency and saturation are of the same order as the gaps between systems.

### Gaps

- The original BEAM and MemoryAgentBench papers predate the cut-off, so their full ability definitions and original baselines are described here only through 2026 papers.
- I found no benchmark in Portuguese or with mixed-language histories; the only cross-lingual evidence is a vendor test (2608.23920) and one adversarial category in ForgetEval.
- No controlled, same-harness leaderboard for the newest benchmarks (LongMemEval-V2, AMA-Bench, MemoryArena, DolphinBench) beyond each paper's own table.
- Peer-review status of these preprints was not checked.

## 3. Knowledge updates and conflict handling: how the best systems detect supersession, and how well it works

### Takeaway

Explicit supersession works well when facts are keyed (entity plus attribute or slot) and a deterministic rule retires the old value while keeping it for audit; the hard, error-prone step is deciding that two statements are about the same fact, and implicit conflicts remain largely unsolved (best measured result 55.2%). Retrieving the new fact is not enough: a stale version sitting beside it in the prompt degrades answers, and several deployed systems mark facts invalid at write time but do not enforce that at read time.

### Cited Findings

- Memory maintenance, not comprehension, is the bottleneck: on LongMemEval's knowledge-update subset, replacing full context with a bounded self-maintained memory drops a frontier model from 92% to 77% (paired McNemar p < 0.005); as the conversation grows 24x, accuracy falls from 68% to 28%, and giving proportionally more memory does not recover it. **[independent]** — [arXiv 2606.27472, v1 2026-06-25](https://arxiv.org/abs/2606.27472)
- A retrieved obsolete statement is worse than an irrelevant one: on MemoryAgentBench single-hop fact consolidation, BM25 accuracy drops from 45% to 32% when the evidence budget grows from 64 to 512 tokens even though the newest statement is in every retrieved set; swapping one unrelated statement for the obsolete competing one cuts accuracy from 100% to 44.6% (Qwen2.5-7B) and from 100% to 87.8% (Qwen3-14B). **[independent]** — [arXiv 2610.36308, v1 2026-10-26](https://arxiv.org/abs/2610.36308)
- "Temporal validity is primarily a property of memory construction": serving only the active value of each correctly keyed slot removed stale exposure in all 1,200 keyed prompts, versus 70.3% of prompts exposing a superseded value without update resolution. Once the active store is fixed, participant-aware BM25 is equivalent to the reference ranker within +/-0.02 and "dense retrieval does not improve clean retrieval". The hard part is key assignment: "Missed merges leave stale values active, whereas false merges silently remove current values"; four LLM key assigners get higher key recall than a rule extractor but lower clean-retrieval rates, and open-domain merge recall on LongMemEval never exceeds 0.062. With out-of-order arrival, the last value to arrive stays active rather than the latest in event time. **[authors' own reference layer] (full text)** — [arXiv 2610.10265, v1 2026-10-07](https://arxiv.org/abs/2610.10265)
- Embedding similarity cannot detect contradiction: cosine similarity separates a contradicted fact from a duplicated one with AUROC 0.59. A deterministic (subject, relation, object) supersession rule writing to a bi-temporal ledger, with no similarity threshold and no LLM call, reaches 0.95-1.00 accuracy on evolving knowledge where plain RAG reaches 0.20-0.47; RAG serves superseded values 15-40% of the time when forced to answer; about 2.1 s versus 16-18 s for LLM-reranking baselines, all with a local 7B model. **[authors' own]** — [arXiv 2606.26511, v1 2026-06-25](https://arxiv.org/abs/2606.26511)
- One concrete detection recipe without an LLM call per fact: "Slot match (exact) signals a likely update; embedding similarity catches the same attribute under a different free-form predicate; content subsumption ... separates contradiction from elaboration"; if clearly contradictory and temporally ordered, set the old fact's invalid_at to the new fact's valid_at and link new.supersedes to the old id. Reported knowledge-update accuracy 87.5% on LongMemEval-S. **[authors' own] (full text)** — [arXiv 2606.09900, v1 2026-06-05](https://arxiv.org/abs/2606.09900)
- How four mechanisms handle supersession, measured on 892 real updating facts: "Mem0 adjudicates the incoming memory, Graphiti invalidates the edge an arrival contradicts, LangMem updates in place, and ERASE edits the entries already stored"; "Graphiti's invalidation fires on the write path and is ignored by its default read path". A retention policy and its retain-everything control return the identical statement at rank 1 for every query, yet differ by 29.5 and 65.6 points in reader accuracy on two readers "when no date is shown". Removing the lexical anchor (full entity name) costs deployed keying mechanisms tens of points of freshness; "entity resolution on both the write path and the query recovers most of the loss". **[independent] (full text)** — [arXiv 2611.19752, v1 2026-11-15](https://arxiv.org/abs/2611.19752)
- Soft revocation is not enforced by default: in five agent-memory systems that mark contradicted facts invalid instead of deleting them, "the revoked fact is returned wherever the revocation label is visible to the retrieval layer, outranks its replacement, and leads agents to the unsafe action". **[independent]** — [arXiv 2609.08258, v1 2026-09-08](https://arxiv.org/abs/2609.08258)
- Keyed revocation versus append-only and last-write-wins: under full reversal of the world state, append-only and last-write-wins memory both score 0.210, below no memory at 0.309, while revocable keyed memory scores 0.950; on clean single-hop consolidation it only matches a strong last-write-wins cache, "confirming that current-key replacement is the decisive operation". **[authors' own]** — [arXiv 2608.07429, v1 2026-08-07](https://arxiv.org/abs/2608.07429)
- Implicit conflicts (a later observation invalidates an earlier memory without explicit negation): best overall 55.2%; "Recognition does not imply application": models often accept outdated assumptions embedded in the user's query and fail to see that a change in one aspect of state should invalidate related memories. The authors' prototype (write-time state consolidation plus propagation-aware search) is offered as a baseline only. **[independent] (full text)** — [arXiv 2605.06527, v1 2026-05-07](https://arxiv.org/abs/2605.06527)
- Cue sensitivity to staleness across model sizes: stale-value reliance is 0.92-1.00 when the task needs stored information; larger checkpoints resist a plainly stale note but are harmed when it appears newer; "Metadata improves accuracy at all four checkpoints ...; pre-resolution yields near-ceiling accuracy across all four". **[independent, small open models]** — [arXiv 2609.01852, v1 2026-09-01](https://arxiv.org/abs/2609.01852)
- "Preserve at write, resolve at read" (DISCERN): a strictly additive bi-temporal provenance graph that never merges confusable entities and never drops superseded values, navigated by an agent with a zero-LLM tool surface and four gated terminal actions including declining to answer. On a synthetic enterprise benchmark, retention and currency are "near-saturated, roughly 0.93 to 0.98 for every competent system"; what separates systems is resolution: abstention F1 0.924 versus at most 0.802, and entity resolution 0.800 "where no baseline exceeds 0.40". **[authors' own, synthetic benchmark]** — [arXiv 2611.15729, v1 2026-11-11](https://arxiv.org/abs/2611.15729)
- Rules decide, the model proposes (LEDGER): "a language model proposes facts and explicit rules decide which value is current, which source to trust, and what to delete", with each fact keeping its source and validity period, plus a fallback search over raw turns: 94.3% / 91.1% (development / held-out seeds) versus 82.1% / 83.3% for full replay on a synthetic coding-agent workload; on LongMemEval it matches full replay (74.8%) with 1% of the context. The authors state the main limitation: the coding workload is synthetic and their own. **[authors' own]** — [arXiv 2611.20927, v1 2026-11-16](https://arxiv.org/abs/2611.20927)
- LLM classification of memory operations is unreliable: a representative memory system chose the correct operation (create, update, reinforce, supersede) only 20% of the time. **[independent, one system]** — [arXiv 2610.22209, v1 2026-10-15](https://arxiv.org/abs/2610.22209)
- Derived state is rarely repaired: "Memory systems also rarely propagate implicit changes, which no new record states"; proposed principles: "Gather inputs along the derivation, store rules with their versions, and maintain derived states through recorded dependencies." **[independent]** — [arXiv 2610.25373, v1 2026-10-18](https://arxiv.org/abs/2610.25373)
- Control state matters as much as content: corrupting only which retained records are visible (validity state), with stored content unchanged, lowers LongMemEval correctness by 40.54 points (95% interval [30.32, 50.71]); enforcement against an oracle restores it. **[independent]** — [arXiv 2610.30698, v1 2026-10-22](https://arxiv.org/abs/2610.30698)
- Provenance-driven reconciliation of derived state on update and delete produces correct final states in all 20 update sequences versus 8 without it. **[authors' own]** — [arXiv 2609.34242, v1 2026-09-28](https://arxiv.org/abs/2609.34242)
- Evidence-grounded "propose, verify, commit" at write time, keeping message-level evidence and revision history: 68.2% on GroupMemBench and 77.9% on EverMemBench, 22.7 and 21.4 points above the strongest evaluated baselines. **[authors' own]** — [arXiv 2609.23465, v1 2026-09-20](https://arxiv.org/abs/2609.23465)
- Benchmarks rarely contain conflicting evidence of different reliability, so last-write-wins looks sufficient on them; belief updating helps only when sources differ in trustworthiness. **[authors' own]** — [arXiv 2606.22030, v1 2026-06-20](https://arxiv.org/abs/2606.22030)
- Lab products on staleness: OpenAI describes time-sensitive memories being revised after the fact (example reported by press: "You are going to Singapore in July" becoming "You went to Singapore in July 2026"). **[vendor; snippet]** — [OpenAI, "Dreaming: Better memory for a more helpful ChatGPT", 2026-06-04](https://openai.com/index/chatgpt-memory-dreaming). Anthropic's documentation for instruction files says "if two instructions contradict each other, Claude may pick one arbitrarily" and offers an audit command that reports outdated or conflicting content and changes nothing until asked. **[vendor documentation, living page read 2026-11-27]** — [Claude Code docs, "How Claude remembers your project"](https://code.claude.com/docs/en/memory)

### Inferences

- The best-supported recipe has three parts: (1) key each claim at write time by canonical entity plus attribute, (2) apply a deterministic rule that marks the older value superseded and links the chain while preserving it, and (3) enforce validity at read time, by default returning only active claims or rendering superseded ones explicitly dated and labelled. Step 3 is where deployed systems were found to fail (2609.08258, 2611.19752).
- Because key assignment and merge decisions are the error-prone step (2610.10265, 2610.22209), an owner-confirmation review is best spent on proposed merges and supersessions (two claims judged to be the same fact) rather than on individual new claims; a false merge silently removes a current value, which a "disputed" label can hold until confirmed.
- For a keyword-only bilingual store, entity resolution on both the write path and the query (2611.19752) is the specific mitigation for missed supersession when the same project or person is named differently in Portuguese and English or by short forms.
- Search results that show a stale and a current claim side by side without dates are the measured worst case (2610.36308, 2611.19752); tool output should always carry event date, label and "superseded by" pointers.
- Implicit conflicts need an offline pass that looks at related claims together (the lint or a consolidation job), with the output being a flag for review, since the best model with the entire history in context manages only 55.2%.

### Gaps

- No 2026 source measures human-in-the-loop confirmation of memory (how many reviews, what precision gain). The only number on review load is from a write-governance policy that needed review on 69.2% of candidates (2607.02579, section 4).
- Handling of event time versus recording time under out-of-order arrival is discussed (2610.10265, 2607.26520) but not solved; this matters for backfilled Git or browser history.
- Implicit-conflict detection has no strong published solution.

## 4. Compiled knowledge (summaries, wiki pages) versus retrieving raw records at query time

### Takeaway

Compiled artifacts measurably help with multi-document synthesis, navigation and token cost, and under tight context budgets, but unverified LLM compilation drops facts, repeated rewriting degrades, and consolidation erases provenance and authority; the best measured configurations serve the compiled layer together with raw search, quote critical facts verbatim, and verify pages against sources.

### Cited Findings

- Anthropic's internal evaluations of LLM-built wikis **[vendor; small evaluation sets, some single runs] (full text)**: on a corpus of about 350,000 files (roughly 420M tokens) with 25 questions, answering from the wiki alone rose from 13% to 48% of graded criteria as wiki-building sessions scaled from 2 to 128; search plus wiki rose from 54% to 61%, versus 53% for search alone, and "also saved about 20,000 tokens per question". On 24 merger questions needing several documents, 87% with the wiki versus 73% with search alone. On a task whose criteria could be met from single documents, "the wiki showed no clear gain"; on another, the wiki grew to 203 KB, 1.77 times the corpus, and "effectively abstracted nothing". When several agents summarized contract terms into one shared table, only 41 of 57 graded facts (72%) survived; with one page per contract "quoting terms word for word", 57 of 57 survived. — [Anthropic Engineering, "The components of agent memory", 2026-11-06](https://www.anthropic.com/engineering/components-of-agent-memory)
- The same post's stated position: "It's also reasonable to consider transcript search as the foundation of Claude's memory. Combining representations (e.g., wikis) with search ... can sometimes be effective. But Claude needs to use compute to maintain memory representations and make sure they don't accumulate errors or hallucinations." **[vendor]** — [Anthropic Engineering, 2026-11-06](https://www.anthropic.com/engineering/components-of-agent-memory)
- The "compilation gap" for LLM wikis served from cache, over 17 domains and 6,800 questions: blind compilation "fails entirely" (2.14-2.32 versus 3.46 out of 5, with a 53-60% catastrophic failure rate). Serving curated knowledge in full context beats RAG (4.38 versus 4.08, 7.3x faster time to first token) but falls below RAG at scale because of attention dilution (3.47 versus 3.64). Evaluating the compiled wiki against diagnostic probes and forcing dropped facts back in recovers 80% of the lost quality in one or two iterations (3.24 versus 3.47) and cuts catastrophic failures by 55% relative; the ablation attributes the gain to targeted diagnosis (+0.95), not generic pinning (+0.16). **[authors' own] (full text)** — [arXiv 2605.07068, v1 2026-05-08](https://arxiv.org/abs/2605.07068)
- Error compounding under continuous rewriting: consolidated memory utility rises and then degrades below the no-memory baseline; "continuously updated textual memory should be treated not as a reliable engine of self-improvement, but as a fragile mechanism that can make more experience produce worse memory". **[independent] (full text)** — [arXiv 2605.12978, v1 2026-05-13](https://arxiv.org/abs/2605.12978)
- Agent-curated versus verbatim stores: curation was the weakest store on one benchmark tier (37.5% versus 78.1% for the verbatim dump on identical questions), while organized stores roughly halve per-query search cost on large material. **[independent] (full text)** — [arXiv 2607.26637, v1 2026-07-29](https://arxiv.org/abs/2607.26637)
- Corroborating independent comparisons: transformed memory stores leave "an accuracy gap relative to raw evidence" even with complete access — [arXiv 2610.30755, v1 2026-10-22](https://arxiv.org/abs/2610.30755); explicit memory gives gains only for some question types and tight budgets — [arXiv 2610.24671, v1 2026-10-17](https://arxiv.org/abs/2610.24671); "coverage-preserving write-time extraction provides the most stable balance" (one system's fast memorize mode beats its fine mode by 25.5 versus 2.5 EM on LoCoMo) — [arXiv 2606.24775, v1 2026-06-23](https://arxiv.org/abs/2606.24775). **[independent] (full text)**
- When compilation wins: under tight budgets (consolidation up to +48% absolute on LongMemEval) — [arXiv 2607.17545, v1 2026-07-20](https://arxiv.org/abs/2607.17545); when the reader gets resolved natural-language entries instead of recency-truncated raw dialogue at matched budget (+42.4 to +72.6 points) — [arXiv 2608.23568, v1 2026-06-05](https://arxiv.org/abs/2608.23568); and for multi-hop questions over documents, where a compiled linked wiki with search / read / follow-link tools and an "Error Book" for self-correction beats HippoRAG 2, LightRAG and GraphRAG by 2.0-8.1 F1 on HotpotQA, MuSiQue and 2WikiMultiHopQA **[authors' own]** — [arXiv 2605.25480, v1 2026-05-25](https://arxiv.org/abs/2605.25480).
- Wiki as an index over raw evidence rather than a replacement: TrajWiki keeps immutable episodic snapshots and claim-level ADD / REVISE / DEPRECATE operations and routes queries "from relevant wiki pages to linked memory trajectories, then to corresponding snapshots and source messages" (improvements on LoCoMo and MedMT, no numbers in the abstract) **[authors' own]** — [arXiv 2608.00967, v1 2026-08-02](https://arxiv.org/abs/2608.00967); a search-friendly wiki built from each system's memory export adds 2.5 and 2.3 points on LoCoMo and LongMemEval-S **[authors' own]** — [arXiv 2609.22231, v1 2026-09-03](https://arxiv.org/abs/2609.22231); a three-layer wiki (document overviews, cross-document topic pages, page-level source records) with a trained navigator **[authors' own]** — [arXiv 2608.29953, v1 2026-08-30](https://arxiv.org/abs/2608.29953); learning wiki edits from downstream navigation feedback adds 6.3 points over the LLM-Wiki base on AuthTrace **[authors' own]** — [arXiv 2607.26604, v1 2026-07-29](https://arxiv.org/abs/2607.26604).
- Long horizons favour stores that keep provenance over budgeted curated summaries: the curated-map memory that leads at three weeks falls to 72.2% recall of early content at nine weeks. **[independent] (full text)** — [arXiv 2607.21962, v1 2026-07-24](https://arxiv.org/abs/2607.21962)
- Consolidation erases authority: across seven consolidators and seven backbones, "authority collapse" (the stored memory implies more authority than its source allows) appears in 48 of 49 configurations; collapsed memories without authority metadata lead to a 50.3% unauthorized-action rate; persisting predicted authority labels cuts the observed rate from 16.9% to 0.0% with task success unchanged. **[independent]** — [arXiv 2608.01679, v1 2026-08-03](https://arxiv.org/abs/2608.01679)
- Consolidation launders provenance: an external observation can be rewritten as apparent user history, keeping an action trigger while erasing its low-trust source; attack success up to 1.000 on vulnerable consolidated memories; with platform-maintained provenance intact, no evaluated unauthorized high-risk action passed the gate. **[authors' own]** — [arXiv 2607.29167, v1 2026-07-31](https://arxiv.org/abs/2607.29167)
- Promoting observations to durable memory needs a gate: a conservative policy (dependency-aware support, counter-evidence retrieval, scope, three outcomes: promote / reject / needs-review) cuts false promotion from 0.597 to 0.040 at 0.960 recall in synthetic tests; on real traces false promotion falls from 0.371 to 0.032 overall but is 0.111 held-out, with 0.692 review burden and 0.448 direct recall; in a human adjudication of 133 high-impact candidates from external coding-agent traces, "none are safe for automatic promotion". **[authors' own]** — [arXiv 2607.02579, v1 2026-06-30](https://arxiv.org/abs/2607.02579)
- A consolidation "quality score" did not predict real transfer accuracy (pooled Spearman rho = -0.24, n = 12, CI spanning zero); "production retrieval systems retain information yet score zero on cross-level transfer". **[authors' own, reported as a negative result]** — [arXiv 2609.33013, v1 2026-09-26](https://arxiv.org/abs/2609.33013)
- Cost evidence: four sequential queries on one domain cost 47K tokens with a self-evolving wiki versus 305K with matched RAG (84.6% saving; four queries only, the 30-day figures are projections) **[authors' own, very small]** — [arXiv 2604.11243, v1 2026-04-13](https://arxiv.org/abs/2604.11243); raw turns cost 3,061 times less to write than LLM extraction — [arXiv 2609.34227, v1 2026-09-28](https://arxiv.org/abs/2609.34227); LLM-maintained views take 15-53 minutes per ingested conversation in leading systems — [arXiv 2605.23986, v1 2026-05-16](https://arxiv.org/abs/2605.23986); a fact memory becomes cheaper than long-context inference after about ten turns at 100k tokens — [arXiv 2603.04814, v1 2026-03-05](https://arxiv.org/abs/2603.04814).
- The design pattern itself: Karpathy's "LLM Wiki" gist describes three layers (immutable raw sources as "your source of truth"; an LLM-owned markdown wiki, "You read it; the LLM writes it"; a schema file with conventions), three operations (ingest, where "a single source might touch 10-15 wiki pages"; query, where "good answers can be filed back into the wiki as new pages"; lint for "contradictions between pages, stale claims that newer sources have superseded" and orphan pages), an index.md and an append-only log.md; it says the index-based approach works "surprisingly well at moderate scale (~100 sources, ~hundreds of pages)". It contains no evaluation. **[opinion / design note; read through a page summary of the first 100,000 characters, which include comments]** — [Karpathy, "LLM Wiki" gist, created 2026-04-04](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)
- Follow-up governance proposal for single-user wikis: the failure mode to design against is "entrenchment under user-coupled drift"; proposes TRIAGE, DECAY, CONTEXTUALIZE, CONSOLIDATE and AUDIT operations and retention of minority hypotheses, so that "accumulated contradictory evidence should have a structural path to updating a centrality-protected dominant interpretation". No empirical results. **[opinion / design]** — [arXiv 2604.12034, v1 2026-04-13](https://arxiv.org/abs/2604.12034)
- Injected (always-loaded) compiled context has its own cost: "Injected memories use up valuable tokens, and an incorrect note can be carried into every session"; longer instruction files reduce adherence, and the product loads only the first 200 lines or 25 KB of its memory index file. **[vendor]** — [Anthropic Engineering, 2026-11-06](https://www.anthropic.com/engineering/components-of-agent-memory); corroborated by the product documentation ("target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence") **[vendor documentation, living page read 2026-11-27]** — [Claude Code docs](https://code.claude.com/docs/en/memory)

### Inferences

- A wiki whose every statement cites a claim, event or commit, with labels computed at read time, versions and a lint tool, already contains the mitigations this literature converges on (source-linked summaries, provenance and authority preserved, reversible edits). The remaining measured risks are: facts dropped at compile time, drift from repeated rewriting, over-expansion, and paraphrase of terms that needed to be exact.
- Concrete checks suggested by the evidence: (1) probe-based verification after each compile, generating questions from the page's cited claims and checking that the page answers them (WiCER's +0.95 came from targeted diagnosis); (2) a size-ratio lint (page bytes versus cited source bytes), since a wiki at 1.77x its corpus "abstracted nothing"; (3) verbatim quoting of decisions, commitments and numbers rather than summary tables (72% to 100% fact survival); (4) rebuilding pages from claims rather than repeatedly rewriting LLM prose, to avoid the schedule-dependent degradation in 2605.12978; (5) never letting page prose state an unconfirmed or disputed claim more assertively than its label (authority collapse).
- Serve both layers: the wiki for orientation and multi-source questions, FTS over raw records for exact details. In Anthropic's test neither alone matched the combination (wiki only 48%, search only 53%, both 61%).
- Promotion of an unconfirmed claim into wiki prose is a "write memory" decision in the sense of 2607.02579; the three-way outcome (promote / reject / needs-review) maps onto unconfirmed / verified / disputed labels, and the paper's finding that automatic promotion was never safe for high-impact items supports keeping the owner review for decisions and commitments.

### Gaps

- No independent, large-scale head-to-head of an LLM-maintained wiki against raw retrieval on personal or work data. Anthropic's numbers are internal, on 24 to 25 questions per task.
- No measurement of wiki drift over months of incremental updates; the longest horizon found is nine simulated weeks (2607.21962), and it tested a curated map, not a cited wiki.
- No study of statement-level citation accuracy in LLM-compiled wikis (how often a cited claim actually supports the sentence).

## 5. What the AI labs themselves published since February 2026

### Takeaway

Anthropic published the most detailed primary material: a November 2026 engineering post with evaluations of memory notes, "dreaming" and wikis, plus Managed Agents memory stores (file-like, versioned, auditable) and the dreaming research preview. OpenAI shipped a "Dreaming" memory architecture for ChatGPT in June 2026 and Google expanded Personal Intelligence and memory import in March 2026, but both could only be seen through search snippets here; I found no Google DeepMind paper on agent memory in the window.

### Inferences

- All three labs converged in 2026 on the same shape: capture during the session, an offline pass ("dreaming") that consolidates and corrects, a user-visible and editable summary, and import/export. Only Anthropic published evaluations that can be inspected, and those are small.
- Anthropic's own framing is cautious about compiled representations and treats transcript search as a legitimate foundation; that is consistent with the independent academic results in sections 1 and 4.
- Features that carry over directly to a local system: immutable versions with point-in-time recovery and content-hash preconditions on writes (Managed Agents stores); a small always-loaded index with details pushed down behind links (200 lines / 25 KB); read-only attachment for reference material as a defence against memory poisoning; optional human review of offline changes before they land; a consolidation pass that checks notes against the original transcript and is focused on information likely to change.
- The model-generation effect (0.364 with memory for an older model versus about 0.83 for the newest on the same task) implies that how well a memory layer works depends on which model reads and writes it; fixed write rules that helped older models hurt newer ones. Prompts and tool descriptions in a memory layer should be re-tested when the model changes.
